### P0-01. 빠른 출석 재저장 시 지각·인정결석이 결석으로 덮어써짐

**현재 동작 (cd043b9)**
- `showAttendance` → `listSession` (`admin.html:1195-1201`): `status==='present'`인 학생만 체크된 상태로 표시합니다 (`:1198`).
- 저장 (`:1203-1206`): **모든 학생**을 체크 여부에 따라 `present` 또는 `absent`로 다시 씁니다.
- 결과: 아무것도 바꾸지 않고 저장해도 지각·인정결석 학생이 결석이 됩니다. 화면에는 '지각'이라고 표시되는데 체크박스는 꺼져 있습니다.

**기대 동작**
1. 학생마다 **[출석] [지각] [결석] [인정결석]** 4개 선택 버튼을 둡니다. 아무것도 선택하지 않은 상태가 '미입력'입니다.
   - 버튼은 `aria-pressed`로 상태를 알리고, 모바일에서 한 줄에 들어가게 하며, 높이 44px을 목표로 합니다.
2. 불러올 때 저장된 상태를 그대로 표시합니다.
3. 저장할 때 **처음 불러온 상태와 비교해 바뀐 학생만** 기록합니다.
   - 기존 기록이 있던 학생을 '미입력'으로 되돌리면 그 문서를 삭제합니다(현재의 '미체크' 의미와 같음).
4. 일괄 동작은 **미입력 학생만** 대상으로 합니다.
   - [미입력 학생 모두 출석]: 수업 시작 때 사용
   - [미입력 학생 모두 결석]: 수업 종료 후 확정할 때 사용
   - 이미 지각·결석·인정결석인 학생은 건드리지 않습니다.
5. 저장 확인창에 변경 내역을 표시합니다. 예: `변경 3명 (출석 2 · 지각 1) · 기록 삭제 0명 · 미입력 1명은 그대로 둡니다`
6. (권장) 저장 직전에 바뀐 학생의 현재 기록을 다시 읽어, 처음 불러온 값과 다르면(다른 기기에서 수정됨) 그 학생은 덮어쓰지 않고 알립니다.
7. 차시 기본 선택: 오늘 날짜의 차시 → 없으면 오늘 이전 가장 최근 차시 → 없으면 첫 차시
8. 문구 수정
   - 상단 안내 "저장 시 체크하지 않은 학생은 결석으로 기록됩니다"를 새 동작에 맞게 바꿉니다.
   - 확인창의 메뉴 경로 "클래스 관리 → 학생별 출석현황"(`:1205`)이 실제 경로와 다르니 바로잡습니다.
9. 학생별 출석현황 모달(`showStudentAttendance`, `admin.html:652`)에서 기존 기록을 '미체크'로 바꾸면, 저장 전에 "기록 삭제 n건"을 확인합니다.

**완료 기준**
- [ ] B01 통과: 출석·지각·인정결석·미입력이 섞인 차시를 변경 없이 저장해도 모든 상태가 유지됨
- [ ] 한 명만 바꿔 저장하면 그 학생 문서만 쓰임 (모의 DB의 쓰기 기록으로 확인)
- [ ] 일괄 버튼은 미입력 학생만 바꿈

### P0-02. 음성 초안이 다른 차시·반·학생에 첨부됨 + 녹음 중 화면 이동 시 마이크가 켜진 채로 남음

**현재 동작**
- 강사: 음성 초안 키가 `제출종류:학생uid`뿐입니다(`admin.html:1103-1110`, `A.voiceDrafts[key]`). 1차시에서 고른 음성이 2차시 같은 학생에게 텍스트만 입력해 등록할 때 2차시 경로로 업로드됩니다. 새 화면에는 선택된 파일이 표시되지 않습니다. 반 변경·로그아웃 때도 지워지지 않습니다.
- 학생: 녹음 결과가 전역 변수 `S.assignmentFile`에 들어갑니다(`index.html:529`, `:532`). 녹음 중 다른 차시로 이동한 뒤 '녹음 종료'를 누르면 이전 차시의 녹음이 현재 차시 과제에 첨부됩니다.
- 공통: 녹음 종료는 버튼으로만 가능합니다(`recordStop`, `index.html:405`). 탭·화면을 이동해도 녹음과 마이크가 계속 켜져 있습니다.

**기대 동작**
1. **초안 키에 대상을 모두 포함합니다.**
   - 강사: `${classId}:${weekId}:${kind}:${studentUid}`
   - 학생: `${uid}:${classId}:${weekId}`
2. **녹음은 시작할 때의 대상에 고정합니다.** 녹음 종료 콜백은 현재 화면이 아니라 녹음을 시작한 대상의 초안에만 파일을 저장합니다.
3. **화면 전환 시 녹음을 자동 중지합니다.** 대상: 탭, 차시, 학생, 반, 메뉴 이동, 로그아웃
   - 마이크 트랙을 모두 종료합니다(`track.stop()`).
   - 녹음은 원래 대상의 초안으로 보관하고 안내합니다. 예: `녹음을 멈췄어요. 1차시 · 김OO 피드백 초안에 보관했어요.`
   - 녹음 중 페이지를 닫거나 새로고침하면 `beforeunload`로 경고합니다.
4. **첨부 상태를 등록 버튼 바로 옆에 보여 줍니다.**
   - 예: `첨부할 음성: recording.webm · 대상: 2차시 · 김OO 학생 [미리 듣기] [첨부 취소]`
   - 해당 대상 화면으로 돌아오면 보관된 초안을 다시 표시합니다.
5. **업로드 직전 대상을 검증합니다.** 업로드 경로의 반·차시·학생이 현재 등록하려는 대상과 다르면 업로드하지 않습니다(방어 코드).
6. 초안을 지우거나 교체할 때 `URL.revokeObjectURL`로 임시 URL을 해제합니다.
7. 학생 과제 제출 시 첨부하는 음성은 **현재 차시의 초안만**입니다.

**완료 기준**
- [ ] B02 통과 (강사 차시 간 음성 오첨부 없음)
- [ ] B03 통과 (학생 녹음 중 탭 이동 → 녹음 중지·마이크 종료·다른 차시 미첨부)
- [ ] 새 테스트: 강사가 학생 A 피드백을 녹음하는 중 학생 B를 선택하면 녹음이 멈추고, 초안은 A에게만 남고, B 화면에는 초안이 없음

### P0-08. 수강 등록 규칙 정리 (D4: 한 학생 한 활성 반)

**현재 동작**
- 강사 '재등록'(`admin.html:1271`): 다른 반에 활성 등록이 있어도 이전 반 등록을 `active`로 바꿉니다 → **활성 반 2개**가 됩니다.
- 학생은 활성 등록 목록의 첫 번째(`active[0]`)를 선택합니다(`index.html:452`, `:509`). 순서가 정해져 있지 않습니다.
- 활성 반이 없고 비활성 기록만 있는 학생에게는 입장 폼이 나오지 않습니다(`index.html:478`). 그래서 **수강 중지된 학생은 다음 기수 반에 새 코드로 들어올 수 없습니다.**

**기대 동작**
1. **강사용 공통 함수 `activateEnrollment(uid, targetClassId)`를 만듭니다.** 하나의 일괄 쓰기(`writeBatch`)에서 다음을 모두 처리합니다.
   - 대상 반 등록을 `active`로 (없으면 생성)
   - 그 학생의 **다른 활성 등록은 모두 `transferred`로**
   - 양쪽 반의 `members/{uid}` 상태 갱신
   - `users/{uid}.assignedClassId` 갱신
   - '반 이동'(`admin.html:1255`)과 '재등록'이 모두 이 함수를 사용합니다.
2. **'재등록' 버튼:** 다른 반에 활성 등록이 있으면 확인창을 띄웁니다. 예: `현재 회화반을 수강 중입니다. 이 반으로 다시 옮길까요?`
3. **학생 화면:** 활성 반이 없고 비활성 기록이 있으면, 기존 안내 문구 아래에 **새 수강 코드 입력 폼도 함께 표시**합니다.
   - 입력한 코드의 반에 이미 등록 기록(`enrollments/{uid}_{cid}`)이 있으면 입장시키지 않고 `이 반은 이전에 등록한 기록이 있어요. 선생님께 다시 등록을 요청해 주세요`라고 안내합니다. 학생이 강사의 수강 중지를 스스로 되돌리지 못하게 하기 위해서입니다(배치 02 보안 규칙과 일치).
   - 확인 방법: 입장 전에 학생이 자기 등록 문서를 `getDoc`으로 조회합니다(본인 문서는 읽기 허용).
4. **활성 등록 선택을 결정적으로 바꿉니다.** 공통 함수 `pickActiveEnrollment(docs)`는 `joinedAt`이 가장 최근인 활성 등록을 선택합니다. `loadStudent`와 `startEnrollmentLive`가 모두 이 함수를 씁니다.
5. **기존 데이터 정리 도구:** 수강생 관리 화면에서 활성 반이 2개 이상인 학생에게 '활성 반 중복' 경고를 표시하고, [이 반만 남기기] 버튼으로 `activateEnrollment`를 실행합니다.
6. 수강생 관리 상태 필터에 **'반 이동'**(`transferred`) 항목을 추가합니다(`admin.html:1212`).

**완료 기준**
- [ ] B04 통과 (재등록 후 활성 등록 1개)
- [ ] B05 통과 (수강 중지 학생에게 새 코드 입력 폼 표시, 같은 반 코드로는 입장 불가 안내)
- [ ] 새 테스트: 활성 등록 2개인 기존 데이터에서 학생은 가장 최근 반을 보고, 강사 화면에 경고가 표시됨
- [ ] 보안 규칙과 충돌하는 쓰기가 없음 (배치 02 규칙이 있으면 해당 규칙 테스트도 통과)

### P0-09. 로그아웃 시 정리 누락

**현재 동작**
- 강사: 로그아웃 후 `onAuthStateChanged`의 `!user` 분기(`admin.html:1302`)가 `adminClearLive()`를 호출하지 않습니다. 실시간 구독이 남아 권한 오류 토스트가 뜰 수 있습니다. 음성 초안·녹음기·대시보드 타이머도 그대로 남습니다.
- 학생: 구독은 정리하지만 녹음기·`S.assignmentFile`·퀴즈 진행 상태는 정리하지 않습니다.

**기대 동작**
1. `resetAdminSession()`, `resetStudentSession()`을 만들어 다음을 모두 정리합니다.
   - 실시간 구독 해제
   - 녹음 중지 + 마이크 트랙 종료
   - 임시 URL 해제
   - 메모리의 초안
   - 타이머(대시보드 `renderTimer` 등)
   - 상태 객체(`A`/`S`)를 초기값으로
2. 호출 위치: 로그아웃 버튼, 강사 권한 없음 화면의 '다른 계정으로 로그인' 버튼, `onAuthStateChanged`의 로그아웃 분기
3. 강사 마지막 선택 반을 저장하는 localStorage 키(`spanish-lms-admin-class`)는 계정별로 분리합니다(키에 uid 포함).

**완료 기준**
- [ ] B06 통과 (로그아웃 후 구독 0개, 오류 토스트 없음)

### P0-10. 실시간 갱신이 작업 중 화면을 덮어씀

**현재 동작**
- 학생: `startWeekLive`(`index.html:440-447`)는 공개 차시 목록이 바뀔 때마다 현재 화면을 다시 그립니다. 입력칸에 커서가 있을 때만 예외입니다.
  - 강사가 **아무 차시나** 저장하면 퀴즈를 풀던 학생의 진행이 1번 문항으로 초기화됩니다(퀴즈는 버튼 조작이라 보호되지 않음).
  - 녹음 중이면 녹음 화면이 사라집니다.
  - 강사가 내용을 바꾸지 않고 저장해도 `updatedAt`이 바뀌어 다시 그려집니다.
- 강사: 과제·복습 관리의 실시간 구독(`admin.html:1059` 부근)이 새 제출이 올 때 목록 전체를 다시 그립니다. 커서가 입력칸에 있을 때만 예외라, 피드백을 쓰다가 '녹음 시작' 버튼을 누른 순간 제출이 오면 입력한 글이 사라집니다.

**기대 동작**
1. **'작업 중' 판정 함수를 만듭니다.**
   - 학생 `isStudentBusy()`: 퀴즈 진행 중(결과 화면 전이고 답을 1개 이상 고름) / 녹음 중 / 과제 입력이 저장본과 다름 / 입력칸 포커스
   - 강사 `isFeedbackBusy()`: 피드백 입력칸에 내용 있음 / 음성 초안 있음 / 녹음 중 / 입력칸 포커스
2. **작업 중이면 다시 그리지 않고 안내 띠를 표시합니다.**
   - 학생: `선생님이 학습 자료를 업데이트했어요. [지금 반영]`
   - 강사: `새 제출 2건이 도착했어요. [목록 새로고침]`
   - [지금 반영]을 눌렀을 때 작업 내용이 사라질 수 있으면 먼저 확인합니다.
3. 작업 중이 아니면 지금처럼 바로 반영합니다.
4. **강사 화면은 가능하면 부분 갱신합니다.** 왼쪽 학생 목록의 개수·배지는 갱신하고, 오른쪽 상세(작성 중)는 유지합니다.
5. **학생이 보던 차시가 비공개로 바뀌거나 삭제되면** 작업 중이어도 안내 띠로 알리고, 그 차시에 제출하려 하면 막고 이유를 보여 줍니다.
6. **실질 변화가 있을 때만 반응합니다.** 비교할 때 `updatedAt` 같은 타임스탬프 필드는 제외하고, 학생이 보고 있는 차시 내용이 실제로 바뀌었는지만 봅니다.

**완료 기준**
- [ ] B07 통과 (퀴즈 진행 중 다른 차시 저장 → 진행 유지 + 안내 띠)
- [ ] 새 테스트: 강사가 피드백 입력 + 음성 초안이 있는 상태에서 새 제출 도착 → 입력 유지, 안내 띠 표시
- [ ] 새 테스트: 강사가 변경 없이 저장 → 학생 화면 다시 그리기 없음
