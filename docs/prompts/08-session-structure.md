# [08] 차시 구조 정리 — 용어 · 생성 경로 · 단일 출처 · 예습 의미 · 공개 상태 (P1-10)

> 먼저 `docs/prompts/00-common.md`를 읽고 따르세요.
> 관련 결정사항: **D1**(용어, 권장 '차시'), **D7**(실제 데이터 유무), **D8**('다음차시 안내' 의미 변경), D9(영상).
> 학생이 화면에 익숙해지기 전에 하는 것이 좋습니다.

## 1. 목표

'수업 한 번'을 가리키는 개념을 하나로 정리합니다. 강사가 차시를 만들고 고치는 경로를 하나로 만들고, 학생에게 무엇이 보이는지 강사가 확신할 수 있게 합니다.

## 2. 배경 (cd043b9)

- 용어 혼재: '주차'(admin 38회, index 3회), '차시'(admin 50회, index 5회), '회차'(admin 2회)
- 차시를 만드는 경로가 두 곳입니다.
  - 반 수정 모달(`classEditor`, `admin.html:612`)의 '+ 차시 추가'
  - 주차 콘텐츠의 '+ 새 주차'(`showCreateWeek`, `admin.html:877`)
- 차시 정보가 두 곳에 저장됩니다: `weeks/{wid}`(`label`, `order`, `sessionDate`)와 `classes/{cid}.schedule[]`(`weekId`, `label`, `date`)
  - 정렬 번호를 바꿔도(`saveWeek`, `admin.html:1011-1020`) `schedule` 순서는 그대로라 출석 화면 순서와 차시 목록 순서가 어긋납니다.
  - `schedule`이 있는 이유: 학생은 공개된 차시 문서만 읽을 수 있어서, 비공개 차시의 날짜(출석 목록, 수강 시작일)를 반 문서의 사본으로 보여 주기 때문입니다.
- '다음차시 안내'는 N주차 문서 안에 N+1차시 예고가 들어가는 구조입니다. 학생이 3주차를 골랐는데 내용은 4차시 이야기라 혼란스럽습니다.

## 3. 요구사항

### 3-1. 용어 통일 (D1)

1. 화면 문구에서 '주차', '회차', '차시'가 쓰인 곳을 모두 찾아 표로 만듭니다(파일·함수·현재 문구·새 문구).
2. D1 확정값으로 바꿉니다. 권장값 기준 예시는 다음과 같습니다.

   | 현재 | 변경 |
   |---|---|
   | 주차별 콘텐츠 / 주차 콘텐츠 | 차시별 학습자료 |
   | + 새 주차 | + 새 차시 |
   | 주차 목록 / 주차 상세 편집 | 차시 목록 / 차시 상세 편집 |
   | 수강생에게 주차 공개 | 학생에게 이 차시 공개 |

3. 코드 식별자(`weeks`, `weekId`, `A.weekId`)와 **Firestore 경로는 바꾸지 않습니다.** 화면 문구만 바꿉니다.
4. 반복 개설은 '기수', 강좌 묶음은 '반'으로 씁니다(D1).

### 3-2. 생성 경로 일원화 · 단일 출처

1. **`weeks` 문서를 기준(source of truth)으로 삼고, `classes.schedule`은 학생 표시용 사본으로 둡니다.**
2. 공통 함수 `syncClassSchedule(cid, batch)`를 만듭니다. `weeks` 문서들을 `order` 순으로 정렬한 사본을 같은 일괄 쓰기 안에서 `schedule`에 기록합니다.
3. 차시를 만들고·고치고·지우는 **모든 경로**에서 이 함수를 씁니다: `classEditor`, `saveWeek`, `showCreateWeek`, `deleteWeekDeep`
4. '+ 새 차시' 버튼은 반 수정 모달의 차시 추가와 **같은 저장 함수**를 씁니다. 차시 이름·번호·날짜를 한 번에 입력합니다.
5. 차시 상세 편집에서 수업 날짜도 수정할 수 있게 합니다(현재는 반 수정 모달에서만 가능).
6. 공통 판정 함수 `sessionState(session, today)` → `'upcoming' | 'today' | 'done'`를 만듭니다. 오늘 날짜는 D10 시간대 기준입니다.
   - 날짜가 없는 차시는 출결 기록이 하나라도 있으면 `'done'`, 없으면 `'upcoming'`
   - 배치 09 대시보드와 출석 화면의 기본 차시 선택에서 씁니다.

### 3-3. '다음차시 안내' → 같은 차시의 '예습' (D8)

**D8 = 의미 변경(권장, 실제 데이터 없을 때)**
- N차시 문서의 예습 = **N차시 수업 전에 볼 자료**입니다.
- 강사 차시 편집의 탭 순서와 이름을 수업 흐름대로 바꿉니다: `[수업 전 · 예습] [수업 후 · 과제] [수업 후 · 복습]`
- 예습 탭 안내: `3차시 수업(10월 30일 목) 전에 학생이 볼 자료입니다`
- 학생 화면의 '다음차시' 화면은 '예습'으로 이름을 바꾸고, `3차시 수업 준비 · 10월 30일 (목)`처럼 대상 차시와 날짜를 표시합니다. 다가오는 차시(`sessionState`가 `upcoming`이거나 `today`인 가장 가까운 공개 차시)를 기본 선택으로 합니다.
- 강사 안내: 수업 전에 예습을 보여 주려면 차시를 공개하되 과제·복습은 꺼 두면 됩니다. 이 흐름을 차시 편집 화면의 짧은 안내로 넣습니다.

**D8 = 유지(실제 데이터가 있을 때)**
- 의미는 그대로 두고, 화면에 대상 차시만 명확히 표시합니다. 예: `4차시 예고 (3차시 문서에 작성)`

### 3-4. 공개 상태를 분명하게

1. 차시 목록 각 행과 편집 화면 상단에 **학생에게 보이는 범위**를 요약합니다.
   - `비공개 초안 — 학생에게 보이지 않아요`
   - `공개됨 — 예습 ✓ · 과제 ✕ · 복습 ✓`
2. **하단 고정 저장 영역:** 저장 상태(배치 07: 저장됨 / 미저장 변경 / 저장 중)와 [저장] 버튼을 화면 하단에 고정합니다.
3. 서식 편집 도구는 자주 쓰는 것(굵게·목록·글자 크기)만 보이게 하고 나머지는 [더 보기]로 접습니다.
4. (선택) **학생 화면 미리보기:** 저장된 차시를 학생 화면과 같은 모양으로 읽기 전용 모달에 보여 줍니다. 구현 비용이 크면 설계안만 보고합니다.

### 3-5. 영상: 큰 파일 직접 업로드 + 유튜브 링크 병행 (D9 확정, 필수)

**D9 확정(2026-10-29):** 복습용 **강의 전체 영상**을 올릴 예정이라 직접 업로드 용량을 크게 합니다(Blaze 요금제 사용 중). 비용 절감 검토를 위해 **유튜브 '일부 공개' 링크 임베드도 함께** 제공합니다.

- 직접 업로드: 현재 2GB 제한(`sizeLimit.video`, `storage.rules`)을 실제 강의 길이에 맞게 올립니다(예: 1~2시간 1080p 영상이 들어갈 크기). 정확한 값은 사용자에게 확인하고, `storage.rules`·`tests/rules`도 함께 고칩니다.
- 큰 파일은 업로드 중 진행률·남은 시간 표시, 실패 시 재시도, 업로드 중 화면 이탈 경고를 넣습니다(현재 `uploadBytesResumable` 사용).
- 예습 자료에 **영상 링크 추가**(유튜브 '일부 공개' 등)를 넣습니다.
- 허용 도메인 목록을 두고 임베드용 주소로 변환합니다.
- 직접 업로드 크기 제한은 D9 값으로 바꾸고, Storage 규칙 수정안을 냅니다.
- 강사 화면에 영상별 '직접 업로드 / 유튜브 링크'를 표시해, 나중에 비용을 비교할 수 있게 합니다.
