### P0-03. 질문 상태 전환 · 상세 배지 갱신 · 최근 대화순 정렬

**현재 동작**
- 학생 답장(`showStudentThread`, `index.html:669`)은 `replies`에만 추가하고 상위 질문의 `status`를 바꾸지 않습니다. 답변 완료된 질문에 학생이 다시 물어도 강사 목록에는 계속 '답변 완료'로 보입니다.
- 강사 답변(`showAdminQuestionThread`, `admin.html:1182`) 후에는 열려 있는 상세 화면의 배지·버튼을 다시 그리지 않고, 지역 변수 `q.status`도 갱신하지 않습니다(`:1183`). 저장은 '답변 완료'인데 화면은 '답변 대기'로 남습니다.
- 목록은 최초 작성 시각순입니다. 오래된 질문에 새 답장이 와도 아래에 묻힙니다.

**기대 동작**
1. 질문 문서에 필드를 추가합니다: `needsTeacherReply`(boolean), `lastMessageAt`(Timestamp), `lastSenderRole`(`'student'`|`'admin'`)
2. 쓰기 규칙
   | 동작 | 함께 갱신할 값 (하나의 writeBatch로) |
   |---|---|
   | 학생 새 질문 | `status:'open'`, `needsTeacherReply:true`, `lastMessageAt`, `lastSenderRole:'student'` |
   | 학생 답장 | 답장 추가 + `status:'open'`, `needsTeacherReply:true`, `lastMessageAt`, `lastSenderRole:'student'` |
   | 강사 답변 | 답장 추가 + `status:'answered'`, `needsTeacherReply:false`, `lastMessageAt`, `lastSenderRole:'admin'`, `answeredAt` |
   | 강사 '답변 완료 표시' (답장 없이 종료, 예: 학생의 감사 인사) | `status:'answered'`, `needsTeacherReply:false` |
   | 강사 '답변 대기로 변경' | `status:'open'`, `needsTeacherReply:true` |
3. '답변 대기' 판정 함수 `needsReply(q)`를 하나 만들어 강사 목록·개수·대시보드에서 공통으로 씁니다. 기준은 `needsTeacherReply === true`이고, 필드가 없는 기존 질문은 `status !== 'answered'`로 판단합니다.
4. 정렬: 학생·강사 목록 모두 `lastMessageAt` 내림차순으로 정렬합니다. 값이 없으면 `createdAt`을 씁니다.
5. 강사 상세 화면: 질문 목록 구독에서 선택된 질문의 상태가 바뀌면 상세 헤더(배지·토글 버튼)도 다시 그립니다. 지역 변수가 아니라 최신 스냅샷 데이터를 기준으로 합니다.
6. 학생 목록 배지: `lastSenderRole==='admin'`이면 '답변 도착', `'student'`면 '답변 대기'로 표시합니다. 필드가 없으면 기존처럼 `status` 기준입니다.
7. 보안 규칙: 학생이 **자기 질문**의 `status`(`'open'`만), `needsTeacherReply`, `lastMessageAt`, `lastSenderRole`, `updatedAt`만 수정할 수 있게 합니다.

**완료 기준**
- [ ] B08 통과: 학생 추가 질문 → 강사 목록 '답변 대기', 개수 증가
- [ ] B09 통과: 강사 답변 직후 상세 배지 '답변 완료', 버튼 '답변 대기로 변경'
- [ ] 새 테스트: 오래된 질문에 새 답장 → 목록 맨 위로

### P0-04. 재제출을 '피드백 완료'로 오판 → '재검토 대기' (최소 구현)

**현재 동작**
- 학생 재제출(`renderAssignment`의 제출 처리, `index.html:541`)은 `text`·`audioPath`·`submittedAt`을 덮어씁니다. 최초 제출 시각이 사라지고 제출 회차 구분도 없습니다.
- 강사 화면 `hasFeedback()`(`admin.html:1076`)은 피드백이 하나라도 있으면 '피드백 완료'로 판정합니다. 학생이 피드백을 반영해 다시 내도 강사는 알 수 없습니다.

**기대 동작** — 배치 06(제출 이력)과 호환되도록 필드 이름을 고정합니다.
1. 학생 제출 시 `runTransaction`으로 현재 문서를 읽고 다음을 저장합니다.
   - `revision`: 기존 값 + 1. 기존 값이 없으면, 문서가 이미 있을 때 2, 없을 때 1
   - `firstSubmittedAt`: 기존 값 유지. 없으면 기존 `submittedAt`, 그것도 없으면 지금 시각
   - `latestSubmittedAt`: 지금 시각
   - `submittedAt`: 기존 화면 호환을 위해 계속 기록
2. 강사 피드백 등록 시 피드백 항목에 `forRevision: 현재 문서의 revision || 1`을 저장합니다.
3. 강사 화면 판정 함수 `reviewState(doc)`를 만듭니다.
   - `'none'`: 미제출
   - `'pending'`: 피드백 없음
   - `'rereview'`: 최신 `revision`에 대한 피드백 없음
   - `'done'`: 피드백 완료
   - `revision`이 없는 기존 문서는 '마지막 피드백 시각 < `submittedAt`'이면 `'rereview'`로 판단합니다.
4. 목록 배지와 필터: '재검토 대기' 배지를 따로 표시하고, '피드백 대기' 필터에 재검토 대기도 포함합니다(또는 별도 필터 항목 추가).
5. 학생 화면: 재제출 후 `수정본을 제출했어요 · 선생님 확인 대기`를 표시합니다. 이전 회차에 대한 피드백에는 `1차 제출에 대한 피드백`처럼 회차를 표시합니다.
6. 복습 결과(`quizResults`)는 이번 배치에서 바꾸지 않습니다.

**완료 기준**
- [ ] B10 통과: 피드백 받은 학생이 재제출 → 강사 목록 '재검토 대기'
- [ ] 재제출해도 `firstSubmittedAt`이 바뀌지 않음
- [ ] 기존 문서(필드 없음)에서도 판정이 동작

### P0-05. 피드백 시각이 UTC로 표시됨 (9시간 차이)

**현재 동작**
- 피드백 `createdAt`은 `new Date().toISOString()`(UTC) 문자열입니다(`admin.html:1109`). 표시할 때 `.slice(0,16).replace('T',' ')`로 잘라 씁니다(`index.html:524`, `admin.html:1025`). 그래서 한국 시간 밤 9시에 쓴 피드백이 '12:00'으로 보입니다.
- 마감일 `dueAt`은 문자열을 그대로 보여 줍니다(`index.html:528`).
- `fmt()`는 브라우저 시간대를 따르고, `shortDate()`(admin)는 별도 형식입니다.

**기대 동작**
1. 공통 함수 `formatDateTime(value, options)`를 만듭니다.
   - 입력: Firestore Timestamp, Date, ISO 문자열, 밀리초 숫자, 시간대 없는 `'YYYY-MM-DDTHH:mm'` 문자열
   - 시간대 없는 문자열은 **D10 시간대(Asia/Seoul)의 시각**으로 해석합니다. `new Date('YYYY-MM-DDTHH:mm')`는 브라우저 시간대로 해석하므로 직접 계산합니다.
   - 출력: `Intl.DateTimeFormat('ko-KR', { timeZone: 'Asia/Seoul', … })`. 옵션으로 요일 포함 여부, 날짜만 표시 등을 고를 수 있게 합니다.
2. `.slice(0,16)` 방식과 `fmt()`·`shortDate()`의 개별 구현을 모두 이 함수로 바꿉니다.
3. 마감 표시 예: `10월 30일 (목) 오후 11:59`

**완료 기준**
- [ ] B11 통과: Playwright 브라우저 시간대를 `Asia/Seoul`과 `Europe/Madrid`로 각각 설정해도 같은 한국 시간으로 표시됨
- [ ] 저장된 문자열 전체를 검색해 잘라 쓰는 시간 표시가 남아 있지 않음

### P0-06. 모달 입력 개선 (Enter 처리 · 피드백 수정창 · 라벨 · 두 파일 통일)

**현재 동작**
- `modalDialog`의 키 처리기(`admin.html:532` 부근, `index.html:411` 부근)는 여러 줄 입력(textarea)에서도 Enter를 누르면 저장합니다. Shift+Enter도 저장되어 **강사 메모에 줄바꿈을 넣을 수 없습니다.**
- 피드백 수정(`updateFeedbackItem`, `admin.html:1027`)은 한 줄 입력칸을 씁니다. 작성은 10,000자 여러 줄인데 수정은 1,000자 한 줄이라, **수정하면 기존 줄바꿈이 사라집니다.**
- 확인 입력 라벨이 '삭제할 반 이름'으로 고정되어 있어 차시 삭제에도 그대로 나옵니다.
- `modalConfirm`의 제목은 모든 동작에서 '변경사항 확인'입니다.
- 두 파일의 모달 복사본이 다릅니다. 한 줄 입력 최대 길이가 학생 150자, 강사 1,000자입니다.
- 한글 입력 조합 중 Enter를 걸러 내는 처리가 없습니다(`isComposing` 검사 없음).

**기대 동작**
1. Enter 처리
   - 한 줄 입력: Enter = 저장. 단, 한글 조합 중(`e.isComposing === true` 또는 `e.keyCode === 229`)이면 무시합니다.
   - 여러 줄 입력: Enter = 줄바꿈, Ctrl+Enter(Mac은 ⌘+Enter) = 저장. 입력칸 아래에 `Ctrl+Enter로 저장` 안내를 표시합니다(Mac은 ⌘).
2. 옵션 추가: `maxLength`, `verifyLabel`, `title`, `confirmText`, `danger`를 호출하는 쪽에서 지정할 수 있게 합니다. 기본값은 두 페이지에서 같게 합니다.
3. 피드백 수정: 여러 줄 입력, 최대 10,000자(작성과 같게), 기존 줄바꿈 보존
4. 확인 라벨: 반 삭제는 '삭제할 반 이름', 차시 삭제는 '삭제할 차시 이름'
5. `modalConfirm(message, {title, confirmText, danger})`: 각 호출부에 맞는 제목을 붙입니다. 예: '수강 코드 재발급', '반 보관', '수강 상태 변경', '출석 저장'
6. 접근성(작은 범위)
   - 모달 안에서 Tab 키가 순환하게 합니다(포커스 트랩).
   - 닫힐 때 모달을 연 버튼으로 포커스를 돌려줍니다.
   - `classEditor`·`showStudentAttendance` 등 별도 모달도 Escape와 포커스를 같은 방식으로 처리합니다.

**완료 기준**
- [ ] B12 통과: 강사 메모에서 Enter = 줄바꿈, Ctrl/Cmd+Enter = 저장
- [ ] B13 통과: 여러 줄 피드백 수정 후에도 줄바꿈 유지
- [ ] 새 테스트: `isComposing: true`인 Enter 이벤트로는 저장되지 않음
- [ ] 두 파일의 모달 동작이 같음 (또는 `common.js` 하나)

### P0-07. 상태 색의 의미 분리

> **2026-10-29 진행 상황:** 디자인 개편에서 토큰(`--success` 등)을 `common.css`에 만들고 `.pill.green/amber/red/gray`를 성공·경고·위험·중립 색으로 다시 정의했습니다. 녹색 테마 잔재도 제거했습니다. **남은 일은 아래 1번(사용처 전수 조사로 '라벨'과 '상태' 구분), 3번(의미 기반 클래스 이름), 4번(기호 병기)입니다.** D2에 따라 '지각·인정결석'은 더 이상 쓰지 않습니다.

**현재 동작**
- 최종 적용 정의(`index.html:189-190`, `admin.html:189-190`)가 다음과 같습니다.
  - `.pill.green` = 배경 `#fce8ed` / 글자 `#9a1b32`
  - `.pill.red` = 배경 `#fff0f2` / 글자 `#a72742`
  - 둘 다 분홍·와인색이라 **정답과 오답, 출석과 결석, 답변 완료와 대기가 색으로 구분되지 않습니다.**
- 반면 반 목록의 `.db-status.active`는 녹색(`#159159`)이라 화면마다 '완료' 색이 다릅니다.
- 초기 녹색 테마의 잔재가 남아 있습니다: `#26785e`(`:174`, 퀴즈 정답 체크), `#235f48`(`:176`, O/X 라벨), `#c5ead6`(로그인 소제목 인라인, `index.html:386`, `admin.html:507`)
- `pill` 클래스가 상태뿐 아니라 라벨에도 쓰입니다. 예: '복수정답/객관식' 문항 유형, 'PRÓXIMA CLASE', 문항 수, 사용자 이름

**기대 동작**
1. **사용처 전수 조사 표**를 먼저 만듭니다. 모든 `pill green|amber|red|gray`와 상태 표시 클래스(`.db-status` 등)에 대해 '파일·함수 / 표시 내용 / 의미(상태 or 라벨) / 새 클래스'를 정리합니다.
2. **의미 토큰을 정의합니다.** 아래 값은 WCAG 2.x AA 일반 텍스트 기준 4.5:1 이상을 확인한 값입니다. 성공 색을 올리브 녹색으로 고른 이유는 브랜드 심벌인 올리브유 병과 어울리기 때문입니다. 값을 바꾸면 대비를 다시 계산해 보고합니다.

   | 토큰 | 글자 / 배경 | 대비 | 쓰는 곳 |
   |---|---|---|---|
   | success | `#3f5f14` / `#eef4e2` | 6.53:1 | 정답, 출석, 제출 완료, 답변 완료, 피드백 완료, 운영 중 |
   | warning | `#8a4a00` / `#fff1dc` | 6.17:1 | 답변 대기, 피드백 대기, 재검토 대기, 완료 차시의 미입력 |
   | danger | `#b3261e` / `#fdecea` | 5.72:1 | 오답, 불참 |
   | neutral | `#5b6168` / `#f0f1f3` | 5.54:1 | 미입력, 비공개, 해당 없음, 보관됨 |
   | brand | `#9a1b32` / `#fce8ed` | 6.95:1 | 상태가 아닌 라벨(문항 유형, 'PRÓXIMA CLASE', 개수, 공개 표시 등) |

3. 의미 기반 클래스 `.pill.success / .warning / .danger / .neutral / .brand`를 추가하고, 1번 표에 따라 모든 사용처를 바꿉니다. 기존 `green/amber/red/gray` 클래스는 사용처가 없어지면 제거합니다.
4. **색만으로 구분하지 않습니다.** 상태 배지 앞에 기호를 붙입니다: `✓` 완료, `!` 대기, `✕` 오답·결석, `–` 미입력·해당 없음
5. 녹색 테마 잔재 3곳을 브랜드·의미 토큰으로 바꿉니다.
6. **새 CSS 레이어를 덧붙이지 않습니다.** 최종 적용 정의를 직접 고치고, 그보다 뒤에서 덮어쓰는 정의가 있는지 검색해 함께 정리합니다.

**완료 기준**
- [ ] 사용처 전수 조사 표 제출
- [ ] 퀴즈 결과·출석(학생 내 정보)·질문 목록·과제 관리 목록 스크린샷(390px, 1440px) 전후 비교
