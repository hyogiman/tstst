## 1. 목표

v1~v10 디자인이 덧칠된 CSS를 **한 벌**로 정리합니다. 아이콘·글꼴·상태 표현을 통일하고, 접근성 기본기를 갖춥니다. 다음 사람이 이어서 고칠 수 있게 README를 씁니다.
**시각적 전면 개편이 아닙니다.** 지금의 브랜드 인상(와인 레드, 카드, 여백)은 유지하고, 코드와 일관성을 정리합니다.

## 2. 현재 상태 (cd043b9)

- 두 파일의 CSS에 디자인 레이어가 쌓여 있습니다: 기본(녹색) → v2(네이비·코랄) → v3 → v4(와인 레드) → v5 → v6 → v7 → v8 → v9 → v10
- `:root` 색 변수 3회 재정의, `!important` admin 43개·index 34개, admin의 고유 HEX 색상 455개
- 웹폰트 3종(DM Sans, Manrope, Noto Sans KR) × 5굵기를 불러오지만 DM Sans는 덮어써져 쓰이지 않습니다.
- 파비콘 `<link rel="icon">` 4개 중복(같은 SVG 3번)
- 목록+상세 화면 3개가 각자 다른 CSS로 구현: `.week-workspace`, `.feedback-workspace`, `.questions-workspace`
- 영어·스페인어·한국어 소제목(eyebrow)이 섞여 있습니다: LEARNING JOURNEY, CLASS INSIGHTS, QUICK ATTENDANCE, PREGUNTAS…
- 강사 화면 제목마다 `(반 이름)`이 붙어 상단 반 선택기와 중복됩니다.
- 배치 05에서 의미 색 토큰(success/warning/danger/neutral/brand)을 이미 도입했습니다.

## 3. 요구사항

### 3-1. 디자인 토큰 (`common.css`의 `:root`)

- **색:** 브랜드(와인 레드 단계), 중립(글자·보조 글자·선·배경·표면), 의미(배치 05 값 유지)
- **글자 크기 단계:** 예) 12 / 13 / 14 / 16 / 18 / 22 / 28 / 34px. 보조 글자도 12px 미만 금지
- **간격·모서리·그림자 단계**
- 보조 글자 색은 배경 대비 4.5:1 이상. 현재 `--muted: #806d72`는 `#fdf8f6` 배경에서 4.58:1로 기준을 겨우 넘으니 더 낮추지 않습니다.

### 3-2. CSS 재구성

1. `common.css`(토큰 + 공통 컴포넌트) + 페이지별 최소 CSS(`student.css`, `admin.css` 또는 각 HTML 안 짧은 `<style>`)
2. 공통 컴포넌트: 버튼, 입력, 카드, 배지(pill), 모달, 토스트, 표, 탭, **목록+상세(`.master-detail`)**, 하단 고정 저장 영역, 안내 띠
3. 목록+상세 화면 3개를 `.master-detail` 하나로 통일합니다.
4. 누적 레이어를 제거하고 **최종 적용 결과만** 남깁니다.
   - `!important`는 0개를 목표로 하고, 남기면 이유를 적습니다.
   - 실제 마크업에서 쓰지 않는 선택자를 제거합니다. 템플릿 문자열 안의 클래스까지 검색해 확인합니다.
5. 녹색 테마 잔재가 남아 있지 않은지 다시 확인합니다.

### 3-3. 아이콘 · 글꼴 · 문구

- **아이콘:** 강사 사이드바 SVG 스타일(선 1.8px, 둥근 끝)로 한 세트를 만들고, 화면 아이콘으로 쓰인 이모지를 바꿉니다. 내용 속 이모지(예: 안내 문구의 👋)는 유지해도 됩니다.
- **글꼴:** 한 종류로 줄입니다(Noto Sans KR의 필요한 굵기만, 또는 Pretendard 한 종류). 고른 이유와 불러오는 용량 전후를 보고합니다.
- **소제목(eyebrow) 언어:** 스페인어로 통일합니다(예: *Tarea*, *Repaso*, *Preguntas*, *Asistencia*, *Panel*). 원치 않으면 없앱니다. 사용자 확인이 필요한 항목이므로 바꿀 목록을 먼저 표로 제시합니다.
- 강사 화면 제목 옆의 `(반 이름)` 반복을 없애고, 상단 반 선택기를 더 눈에 띄게 합니다.
- 파비콘은 PNG 1개 + SVG 1개로 정리합니다.

### 3-4. 접근성

- **라벨:** 모든 입력(차시 선택, 답안, 파일 선택, 검색, 필터)에 `<label for>` 또는 `aria-label`을 연결합니다.
- **모달:** 열 때 포커스 이동, 안에서 Tab 순환, 닫을 때 원래 버튼으로 복귀(배치 05의 처리를 모든 모달에 적용)
- **터치 크기:** 주요 버튼 44px을 목표로 합니다. WCAG 2.2 AA의 최소 기준(24×24px)은 하한일 뿐이니 '법정 기준 44px'이라고 쓰지 않습니다.
- **파일 선택:** 기본 'Choose File' 대신 숨긴 `input[type=file]` + `<label>` 버튼(`음성 파일 선택`, `이미지 선택`)과 선택한 파일 이름 표시
- **색 외 단서:** 상태는 색 + 기호 + 글자(배치 05)
- **키보드:** 사이드바·하단 탭·`⋯` 메뉴·탭 목록을 키보드로 조작할 수 있게 합니다.
- **긴 문자열:** 긴 이름, 긴 스페인어 문장, 브라우저 200% 확대에서 레이아웃이 깨지지 않게 합니다.

### 3-5. 미사용 코드 정리

- `PAGES` 상수(`admin.html:555`)처럼 쓰이지 않는 코드를 제거합니다.
- 구버전 호환 코드('수강생' 이름 복구, `correctIndex` 호환, 단일 `feedback` 필드 호환)는 **D7 = 실제 데이터 없음일 때만** 제거하고, 제거 목록을 보고합니다.

### 3-6. README (`README.md`)

- 구성(파일·폴더), 로컬 실행(정적 서버), 배포(정적 호스팅 + `?v=` 캐시 버전 갱신), Firebase 설정
- 보안 규칙 배포·되돌리기, 데이터 구조(`00-common.md` 2장 요약), 테스트 실행
