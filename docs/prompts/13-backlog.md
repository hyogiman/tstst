## P4-01. 문항 분석 (문항별 정답률 · 오답 선택지 분포)

> **D5 확정(2026-10-29):** 강사의 난이도 조절을 위해 퀴즈 통계가 필요하므로 **배치 09(대시보드)에서 함께 구현**합니다. 아래는 상세 요구사항입니다.

- **왜:** "반 학생 60%가 같은 오답을 골랐다"는 공통 오개념의 신호입니다. 다음 수업 도입부 5분을 그 문항 해설에 쓰는 것이 가장 쉬운 데이터 기반 수업 설계입니다.
- **선행:** 배치 06 (퀴즈 버전, 문항 ID 기반 답안)
- **요구:**
  - 차시별 퀴즈에서 문항마다 첫 응시 정답률(p값, 고전검사이론의 문항 난이도)과 선택지별 선택 비율을 보여 줍니다.
  - 같은 버전의 응시만 집계하고, 버전이 다른 응시와 legacy 기록은 분리합니다. 항상 n명을 표시합니다.
  - 정답률이 낮은 문항을 위로 정렬하고, "가장 많이 고른 오답"을 강조합니다.
  - **변별도(상·하위 집단 정답률 차이)는 소규모 반에서 통계적으로 불안정**하니 계산하지 않거나 '참고용, n<20'으로 표시합니다.
- **완료 기준:** 가상 데이터에서 문항별 정답률·선택 비율이 수작업 계산과 일치. 버전이 섞이지 않음

## P4-02. 학습 목표 태그 · 영역별 약점

- **왜:** 문항 하나가 아니라 "ser/estar", "성·수 일치", "카페 주문"처럼 **가르친 단위**로 약점을 봐야 다음 수업을 바꿀 수 있습니다.
- **요구:**
  - 강사 퀴즈 편집기에서 문항마다 태그(여러 개 가능)를 붙입니다. 태그는 반 단위 목록에서 고르거나 새로 만듭니다.
  - 과제에도 태그를 붙일 수 있게 합니다(선택).
  - 대시보드 상세에 태그별 첫 응시 정답률과 문항 수를 보여 줍니다. **문항이 3개 미만인 태그는 '판단 보류'**로 표시합니다.
  - 정식 언어 등급(CEFR 등)으로 자동 환산하지 않습니다. CEFR은 반 수준(A1·A2 등)을 적는 참고 정보로만 둡니다.

## P4-03. 말하기·쓰기 간단 루브릭 + 포트폴리오

- **왜:** 객관식 점수는 실제 표현 능력을 보여 주지 못합니다. 첫 수업의 30~60초 자기소개와 몇 주 뒤의 녹음을 나란히 들으면, 학생도 강사도 성장을 체감합니다.
- **선행:** 배치 06 (제출 이력, 녹음 길이)
- **요구:**
  - 루브릭 4항목, 각 0~3점: **과제 수행 / 의미 전달(이해 가능성) / 문법 / 어휘**. 각 점수의 설명 문장을 강사가 편집할 수 있게 합니다.
  - 발음은 '원어민과 비슷한가'가 아니라 **'알아듣기 쉬운가'**를 봅니다. 외국인 억양이 강해도 이해 가능성은 높을 수 있다는 연구(Munro & Derwing, 1995)를 근거로 둡니다.
  - 평가하지 않은 항목은 0점이 아니라 '평가 안 함'으로 둡니다.
  - 점수와 함께 **다음 시도의 구체적 목표 한 줄**을 남깁니다. 예: `연결 표현(pero, porque) 2개 써 보기`
  - 학생 포트폴리오: 같은 유형 과제의 첫 녹음과 최근 녹음을 나란히 재생하고, 루브릭 점수 변화를 표시합니다.
- **완료 기준:** 루브릭 저장·수정·학생 표시, 포트폴리오 비교 화면, 미평가 항목이 평균에 0으로 들어가지 않음

## P4-04. 수업 후 1분 체크인

- **왜:** 정량 데이터가 놓치는 "학생이 어디서 막혔는가"를 바로 얻습니다. Angelo & Cross의 『Classroom Assessment Techniques』(1993)에 소개된 대표 기법 **'Muddiest Point(가장 헷갈렸던 점)'**를 응용합니다.
- **요구:**
  - 차시가 끝나면(`sessionState === 'done'`) 학생 홈에 3문항 체크인을 보여 줍니다: 오늘 이해도(1~5), 자신감(1~5), "가장 헷갈렸던 한 가지"(선택, 200자)
  - 강사 화면: 차시별 평균과 응답 수, 자유 응답 목록. 같은 표현이 반복되면 묶어 보여 줍니다(단순 문자열 빈도면 충분)
  - (선택) 자신감과 퀴즈 첫 점수 비교: "자신감은 높은데 점수가 낮은" 경우를 강사에게만 보여 주는 참고 정보
  - 데이터: `weeks/{wid}/checkins/{uid}` (본인 + 강사만 읽기)

## P4-05. 며칠 뒤 확인 문제 · 오답 노트

- **왜:** 배운 직후에 맞히는 것과 며칠 뒤에도 기억하는 것은 다릅니다. 시간이 지나면 기억이 빠르게 줄어든다는 에빙하우스의 망각곡선(1885), 다시 떠올리는 연습이 기억을 강화한다는 '시험 효과' 연구(Roediger & Karpicke, 2006)가 근거입니다.
- **요구:**
  - 오답 노트: 학생이 틀린 문항을 차시 구분 없이 모아 다시 풉니다(점수에 반영하지 않음).
  - 지연 확인: 강사가 지정한 일수(예: 3일·7일) 뒤 학생 홈에 이전 차시 문항 몇 개를 띄웁니다. 같은 학습 목표의 다른 문항이면 더 좋습니다.
  - 결과는 '즉시 정답률'과 '지연 정답률'로 따로 집계합니다.

## P4-06. 피드백 문구 템플릿 · 3질문 입력틀

- **왜:** 학생이 많아지면 피드백 작성 시간이 가장 큰 부담이 됩니다. 좋은 피드백은 *어디로 가는가(목표) / 지금 어디인가(현재) / 다음은 무엇인가(다음 단계)*의 세 질문에 답한다는 Hattie & Timperley(2007)의 틀을 입력 화면에 반영합니다.
- **요구:**
  - 피드백 작성창을 선택적으로 3칸으로 나눕니다: `잘한 점` / `고칠 점` / `다음에 해 볼 것`. 저장할 때는 한 덩어리로 합쳐도 됩니다.
  - 자주 쓰는 문구를 저장하고 한 번에 넣습니다. 예: `악센트 위치를 다시 확인해 보세요`, `ser와 estar의 차이를 다시 볼까요?`
  - 템플릿은 강사 계정 단위로 저장합니다.

## P4-07. 콘텐츠 복사 (차시 → 차시, 반 → 반) — 2기 개강 전에 필요

- **왜:** 같은 강좌를 기수별로 반복 운영하면, 매번 과제·퀴즈·예습 자료를 다시 입력하는 것이 가장 큰 운영 부담입니다.
- **선행:** 배치 08 (차시 구조 정리)
- **요구:**
  - 차시 하나 또는 반 전체의 차시 구성(이름·순서·과제·퀴즈·예습)을 다른 반으로 복사합니다. **학생 데이터(제출·응시·출결·질문)는 복사하지 않습니다.**
  - 날짜는 비우거나 '첫 수업일 + 7일 간격'으로 다시 채웁니다. 복사한 차시는 모두 비공개로 시작합니다.
  - **Storage 파일 처리 결정이 필요합니다.** 현재 학생의 예습 자료 읽기 권한이 반 경로(`classes/{cid}/previews/…`) 기준이라, 다른 반 파일 경로를 참조하면 새 반 학생이 열 수 없습니다. ① 파일을 새 반 경로로 다시 업로드하거나(영상은 무거움) ② 공용 자료 경로(예: `library/…`)와 규칙을 새로 만드는 방법이 있습니다. 두 방안의 장단점을 제시하고 승인을 받습니다.
  - 퀴즈 버전은 새 반에서 1부터 시작합니다.

- 요구: 반 공지 목록(제목·내용·고정 여부), 학생 홈 상단 표시, 새 공지 배지, 강사 작성·수정·삭제

- 요구: 유튜브 링크를 넣으면 영상 ID를 검증해 `https://www.youtube-nocookie.com/embed/{id}`(개인정보 보호 강화 모드)로 임베드합니다. '일부 공개' 영상도 임베드할 수 있습니다. 허용 도메인 외에는 거부합니다. 학생 화면에 `영상은 유튜브에서 재생됩니다` 안내를 표시합니다.

## P4-10. 기수 간 같은 차시 비교

- **왜:** "1기와 2기 모두 4차시 정답률이 낮다"면 반의 문제가 아니라 **4차시 교안의 문제**입니다. 커크패트릭(Kirkpatrick) 평가 모형으로 보면 2단계(학습) 결과를 교육 설계 개선에 되먹이는 구조입니다.
- **선행:** P4-07 (복사로 만든 차시끼리 연결: `sourceWeekId` 등)
- **요구:** 같은 원본 차시에서 나온 차시끼리 출석·지각률, 정시 제출률, 첫 응시 정답률, 문항별 정답률을 나란히 보여 줍니다. 기수마다 n을 표시합니다.

## P4-11. 퀴즈 유형 확장 (스페인어 특화)

- **단답형:** 정답 문자열 여러 개 허용, 대소문자·앞뒤 공백·¿¡ 무시
  - **악센트 처리 옵션을 문항마다 둡니다**: '악센트 틀리면 부분 정답' / '악센트까지 정확해야 정답'. 악센트가 뜻을 바꾸는 경우가 있기 때문입니다. 예: *si*(만약) / *sí*(네), *papa*(교황, 중남미에서는 감자) / *papá*(아빠), *esta*(이것, 지시형용사) / *está*(~에 있다, estar 동사)
  - **ñ는 n과 다른 글자로 취급합니다.** 유니코드 정규화(NFD)로 발음 구별 기호를 일괄 제거하면 ñ가 n이 되므로, ñ는 예외 처리합니다. 예: *cana*(흰머리) / *caña*(갈대, 스페인에서는 작은 생맥주 한 잔)
- **듣기형:** 문항에 음성 첨부 → 듣고 고르기
- **동사 변화표:** 인칭(yo, tú, él/ella/usted, nosotros, vosotros, ellos/ellas/ustedes)별 입력. *vosotros*는 주로 스페인에서 쓰고 중남미에서는 거의 쓰지 않으므로, 반 설정으로 켜고 끌 수 있게 합니다.
- **문장 배열:** 단어 카드 순서 맞추기
- 기존 채점 함수와 응시 기록 구조(배치 06)를 확장하는 설계안을 먼저 제시합니다.

## P4-12. 예습 확인

- **왜:** 페이지를 열었다는 것과 학습했다는 것은 다릅니다. 자동 열람 기록 대신 **학생의 명시적 행동**으로 기록합니다.
- **요구:** 예습 자료 아래에 [확인했어요] 버튼 또는 1~2문항 확인 문제를 둡니다. 대시보드에는 '예습 확인 n/대상 n'으로만 표시하고 학습 성취로 해석하지 않습니다.

## P4-13. 수료 리포트

- **요구:** 기수 종료 시 학생별 한 장 리포트(출석, 제출 수, 누적 말하기 시간, 루브릭 변화, 강사 총평)를 만듭니다. 인쇄용 CSS + 브라우저 인쇄(PDF 저장)로 구현합니다. 학생에게 공개 여부를 강사가 정합니다.

## P4-14. 서버 채점 (D5가 '평가 반영'일 때만)

- **요구:** 정답을 강사 전용 문서로 분리하고, 채점은 Cloud Functions(호출형 함수)에서 합니다. 학생은 답안만 제출하고 점수는 서버가 기록합니다.
- **주의:** Cloud Functions 배포에는 Blaze(종량제) 요금제가 필요합니다. 비용·운영 부담을 먼저 사용자에게 설명하고 승인을 받습니다.
