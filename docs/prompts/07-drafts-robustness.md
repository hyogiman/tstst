# [07] 작업 보존 · 오류 처리 · 임시 파일 정리 (P1-07, P1-08, P1-09)

> 먼저 `docs/prompts/00-common.md`를 읽고 따르세요.
> 배치 04의 음성 초안 키 규칙(`반:차시:종류:학생`)과 '작업 중' 판정 함수를 그대로 이어서 씁니다.
> 테스트 하네스가 있으면 **B15~B17**이 이 배치의 목표입니다.

## 1. 목표

학생과 강사가 **쓰던 내용을 잃지 않게** 하고, 불러오기에 실패했을 때 '미제출'처럼 잘못 보이지 않게 하며, 저장하지 않은 업로드 파일이 남지 않게 합니다.

---

## 2. 요구사항

### P1-07. 작성 중 초안 보존

**현재 동작 (ChatGPT 리뷰 F03에서 재현됨)**
1. 강사가 차시 과제 제목을 수정 → 다른 차시 선택 → 돌아오면 원래 값 (`drawWeekEditor`, `admin.html:956`)
2. 강사가 학생 A 피드백 입력 → 학생 B 선택 → A로 돌아오면 빈 입력칸 (`renderDetail`, `admin.html:1082`)
3. 학생이 과제 답안 수정 → 다른 탭 → 돌아오면 이전 제출 내용 (`renderAssignment`, `index.html:526`)
4. 학생이 퀴즈를 풀다 다른 탭에 다녀오면 처음부터 (`S.quiz=null`)

**기대 동작**

| 대상 | 보관 위치·키 | 복원 | 새로고침 후 |
|---|---|---|---|
| 학생 과제 텍스트 | localStorage `senorayu:draft:{uid}:{cid}:{wid}:assignment`, 입력 후 0.5초 뒤 저장 | 저장본과 다르면 복원 + 안내 `이 기기에 임시 저장된 답안을 불러왔어요 [임시 저장본 지우기]` | 복원됨 |
| 학생 퀴즈 진행 | 메모리 + sessionStorage, 키 `{uid}:{cid}:{wid}:{quizVersion}` (답, 현재 문항, 보기 섞인 순서) | [이어서 풀기] / [처음부터] | 같은 탭이면 복원 |
| 강사 피드백 텍스트 | 메모리 + localStorage `senorayu:draft:{adminUid}:{cid}:{wid}:{kind}:{studentUid}` | 해당 학생 상세를 열 때 복원, 목록에 `작성 중` 표시 | 복원됨 |
| 강사 음성 초안 | 메모리만 (배치 04) | 해당 학생 상세에서 다시 표시 | **복원 안 됨** → 경고 |
| 강사 차시 편집 | 열 때 값의 스냅샷과 비교해 '미저장 변경' 판정 | 복원하지 않고 **이탈 확인** | 복원 안 됨 → 경고 |

- **이탈 확인 (강사 차시 편집):** 다른 차시 선택, 메뉴 이동, 반 변경, 로그아웃 전에 미저장 변경이 있으면 묻습니다. `저장하지 않은 변경사항이 있어요 [저장하고 이동] [버리고 이동] [취소]`
- **저장 상태 표시:** 차시 편집 하단에 고정 영역을 두고 `저장됨 · 21:03` / `저장하지 않은 변경 있음` / `저장 중…`을 보여 줍니다(배치 08의 하단 고정 저장 영역과 같은 컴포넌트).
- **페이지 닫기·새로고침:** 미저장 변경, 녹음, 음성 초안이 있으면 `beforeunload`로 경고합니다.
- **제출·등록 성공 시** 해당 초안을 삭제합니다.
- **로그아웃 시:** 그 사용자의 localStorage 초안을 삭제합니다. 공용 PC에서 다음 사람이 보지 않게 하기 위해서입니다. 학생 로그아웃 버튼 근처나 확인창에 `로그아웃하면 이 기기의 임시 저장 답안이 지워져요`라고 알립니다.
- 키에 uid가 들어가므로 **다른 계정에는 절대 표시되지 않아야** 합니다.

### P1-08. 조회 실패 처리 · 학생용 오류 문구 · CDN 실패 안내

**현재 동작**
- `renderAssignment`·`renderQuiz`의 `getDoc`(`index.html:529`, `:567`)에 오류 처리가 없습니다. 실패하면 '제출 기록 확인 중'이 계속 표시됩니다.
- 오류 문구 함수 `ex()`(`index.html:298`)가 학생에게도 `Storage 보안 규칙을 확인해 주세요` 같은 개발 용어를 보여 줍니다.
- Firebase CDN 로드에 실패하면 완전한 백지 화면이 됩니다.

**기대 동작**
1. 학생·강사 화면의 모든 비동기 조회에 지역 오류 처리를 넣습니다. 실패하면 그 카드 안에 `기록을 불러오지 못했어요. [다시 시도]`를 표시하고, 상세는 `console.error`에만 남깁니다.
   - **'미제출·미입력'과 '불러오지 못함'을 화면에서 구분합니다.**
2. 오류 문구를 학생용과 강사용으로 나눕니다.
   - 학생 예: `권한이 없어 열 수 없어요. 선생님께 문의해 주세요`
   - 강사: 기존 상세 문구 유지
3. **CDN 실패 안내:** 모듈 밖에 작은 일반 스크립트를 두고, 8초 안에 앱이 시작 신호(예: `window.__appStarted = true`)를 남기지 않으면 다음을 표시합니다.
   `화면을 불러오지 못했어요. 네트워크를 확인하고 새로고침해 주세요. 회사·학교 네트워크라면 다른 네트워크로 시도해 보세요. [새로고침]`
   `<noscript>` 안내도 추가합니다.
4. (선택) 오프라인 표시: `offline` 이벤트에 상단 띠 `인터넷 연결이 끊겼어요`

### P1-09. 저장하지 않은 업로드 파일 정리

**현재 동작:** 강사가 예습 자료(이미지·영상·파일)를 올린 뒤 저장하지 않고 떠나면, 어느 문서에도 연결되지 않은 파일이 Storage에 남습니다(`uploadPreviewFile`, `admin.html:998`).

**기대 동작**
1. 이번 편집에서 업로드했지만 아직 저장하지 않은 파일 목록(`unsavedUploads`)을 추적합니다.
   - 저장하면 목록을 비웁니다.
   - [버리고 이동]을 고르면 그 파일들을 삭제합니다.
2. 업로드는 성공했는데 문서 저장이 실패하면(학생 과제 음성, 강사 피드백 음성, 예습 자료) 방금 올린 파일 삭제를 시도합니다.
3. 브라우저를 그냥 닫으면 정리할 수 없습니다. 이 한계를 보고하고, (선택) 강사용 '연결되지 않은 파일 점검' 도구를 제안합니다. 예: 차시의 `previews/` 경로 파일 목록과 문서 참조를 비교해 목록 표시 후 선택 삭제
