# [09] 대시보드 재구성 — 정확한 기준 · 처리할 일 · 진행표 (P2-01 ~ P2-04)

> 먼저 `docs/prompts/00-common.md`를 읽고 따르세요.
> 관련 결정사항(2026-10-29 확정): **D2** 출석은 출석·불참 두 가지, **D3** 통계는 마감 기준이 아니라 **실시간**, 늦은 제출 인정, **D5** 난이도 조절을 위한 **퀴즈 통계 필요**(문항 분석 포함), D10 Asia/Seoul.
> 선행 배치: 05(`needsReply`, `reviewState`), 06(`wasActiveAt`, `firstAttempt.legacy`, 퀴즈 버전), 08(`sessionState`). 선행 배치가 빠졌으면 해당 지표는 현재 데이터로 가능한 범위만 만들고, 부족한 점을 화면 설명과 보고서에 적습니다.
> 테스트 하네스가 있으면 **B14**가 이 배치의 목표 중 하나입니다.

## 1. 목표

대시보드가 세 가지 질문에 답하게 합니다.

1. **오늘 내가 처리할 일은?** → 처리할 일 카드
2. **반 전체가 잘 따라오고 있나?** → 기준이 분명한 핵심 지표
3. **누구를 챙겨야 하나?** → 학생 × 차시 진행표

대시보드에는 편집 기능을 넣지 않습니다(현재 원칙 유지). 숫자를 누르면 **필터가 적용된 기존 관리 화면**으로 이동합니다.

| 첫 퀴즈 정답률에 참여율이 없고, legacy 보정값도 '첫 응시'로 집계 | `:750-756` |

## 3. 요구사항

### 3-1. 집계 로직을 순수 함수로 분리

- `computeDashboard({sessions, enrollments, events, attendance, submissions, quizResults, questions}, today)` → 화면에 필요한 모든 숫자를 반환합니다.
- 화면 그리기 코드와 분리해 하네스에서 **단위 테스트**할 수 있게 합니다. 테스트에는 가상 데이터와 기대 숫자를 직접 적습니다.

### 3-2. 기준 정의

| 개념 | 정의 |
|---|---|
| 완료 차시 | `sessionState(session, today) === 'done'` (배치 08) |
| 최근 차시 차트 | 완료 차시 중 최근 8개 |
| 차시 대상자 | 그 차시 날짜에 수강 중이던 학생 (`wasActiveAt`, 배치 06). 추정이면 `추정` 표시. 면제 학생은 제외 |
| 출석률 (D2) | 출석 ÷ (출석 + 불참). 미입력은 제외하고 입력률로 따로 표시 |
| 출결 입력률 | 상태가 입력된 건수 ÷ (완료 차시 × 대상자). 오늘 차시는 수업 종료 전이므로 미입력 경고에서 제외 |
| 과제 제출률 (D3) | **실시간**: 학생에게 공개된 과제 × 대상자 중 지금까지 제출한 비율. 마감 기준 정시·늦음 구분 없음(늦은 제출도 제출로 인정). 공개 전 과제는 제외 |
| 복습 참여율 | 완료 차시의 공개 퀴즈에서 응시한 대상자 ÷ 대상자 |
| 첫 응시 정답률 | **실제 첫 응시**만 평균. `legacy` 보정값은 제외하고 제외한 건수를 표시 |

### 3-3. 화면 구성 (위에서 아래로)

1. **상단 한 줄:** `초급반 · 기준 10월 29일 (수) · 마지막 갱신 21:03`
   - 대형 배너는 제거하거나 높이를 크게 줄이고(예: 96px 이하), 모바일에서는 숨깁니다.
   - '운영 클래스 N개'는 작게 맥락 정보로만 둡니다.
2. **처리할 일 카드** (0건이면 `처리할 일이 없어요 ✓`)

   | 카드 | 계산 | 누르면 |
   |---|---|---|
   | 피드백 대기 | `reviewState === 'pending'` | 과제·복습 관리, 해당 차시, 필터 '피드백 대기' |
   | 재검토 대기 | `reviewState === 'rereview'` | 같은 화면, 필터 '재검토 대기' |
   | 답변 대기 질문 | `needsReply(q)` | 질문함, 필터 '답변 대기' |
   | 출결 미입력 | 완료 차시 중 대상자 대비 미입력 | 출석 화면, 해당 차시 |
   | 공개 누락 | 3일 안에 수업인데 비공개이거나 예습이 꺼진 차시 | 차시별 학습자료, 해당 차시 |

   - 여러 차시에 걸쳐 있으면 카드를 펼쳐 차시별 건수를 보여 줍니다.
   - 필터가 적용된 화면으로 이동하려면 `navigateAdminPage(key, {weekId, filter})`처럼 이동 함수에 매개변수를 추가합니다.
3. **핵심 지표 3개** — 퍼센트 옆에 항상 건수를 표시합니다.
   - `출석률 92% (23/25건) · 입력 25/28건`
   - `과제 제출 75% (12/16건) · 이번 차시 2/4명 제출`
   - `첫 응시 정답률 67% · 응시 3/4명 (학생·차시 12건)`
   - 각 지표의 ⓘ를 누르면 3-2의 정의를 보여 줍니다(현재 하단 '집계 기준' 문단을 대체).
4. **차시별 추이:** 최근 완료 8차시의 출석·지각률 / 정시 제출률 / 첫 응시 정답률
   - 막대나 선 옆에 n을 표시합니다.
   - 데이터가 없는 차시는 '기록 없음'으로 표시하고 0으로 그리지 않습니다.
5. **학생 × 차시 진행표:** 최근 완료 4~8차시

   | 칸 | 표시 |
   |---|---|
   | 출결 | `● 출석` `○ 불참` `· 미입력` (빈칸 = 대상 아님) |
   | 과제 | `✓ 제출` `✕ 미제출` `– 과제 없음` |
   | 복습 | 첫 응시 점수 % 또는 `미응시` |

   - 색 + 기호 + 글자를 함께 쓰고, 범례를 둡니다.
   - 학생 이름을 누르면 학생 상세(배치 11, 없으면 수강생 관리)로 이동합니다.
   - 모바일에서는 이름 열을 고정하고 가로 스크롤합니다.
6. **(선택) 확인이 필요한 학생:** 설명 가능한 규칙만 사용합니다.
   - 규칙 예: `최근 완료 3차시 중 불참 2회 이상`, `공개된 과제 2회 연속 미제출`, `최근 2차시 복습 미응시`
   - 이유 문장을 함께 보여 줍니다. 예: `이OO — 2·3차시 연속 결석, 3차시 과제 미제출`
   - 강사에게만 보이고, 점수화·등수·'위험' 낙인 표현을 쓰지 않습니다. 기준값은 코드 상단 상수로 둡니다.

### 3-4. 퀴즈 문항 분석 (D5: 강사의 난이도 조절용, P4-01에서 상향)

- 차시별 퀴즈의 **문항별 첫 응시 정답률**과 **보기별 선택 비율**을 보여 주는 상세 화면을 대시보드에서 연결합니다(배치 06의 퀴즈 버전 기록 필요).
- 정답률이 낮은 문항을 위로 정렬하고, 가장 많이 고른 오답을 강조합니다. 항상 n명을 함께 표시합니다.
- 같은 버전의 응시만 집계하고, 버전이 다르거나 legacy 기록은 분리합니다.
- 자세한 요구는 `docs/prompts/13-backlog.md`의 P4-01을 따릅니다.

### 3-5. 분석 원칙 (화면 설계 기준으로 지킬 것)

1. 퍼센트 옆에 항상 n을 표시합니다. 4명 반에서는 1명이 25%p를 바꿉니다.
2. 미응시·미제출을 0점으로 계산하지 않습니다. 참여와 성취를 따로 보여 줍니다.
3. 반복 응시를 독립된 학생처럼 더하지 않습니다. '첫 응시' 등 기준을 명시합니다.
4. 반 평균과 개인 추이를 함께 봅니다(진행표).
5. **학생 화면에는 다른 학생과의 비교·순위를 보여 주지 않습니다.** 측정치가 목표가 되면 측정 자체가 왜곡된다는 굿하트의 법칙에 따른 원칙입니다.
6. 페이지 열람·클릭 수를 학습의 증거로 쓰지 않습니다. 과제·대화·표현 결과를 우선합니다.

### 3-6. 성능

- 실시간 구독은 '최근 완료 8차시 + 진행 중 차시'로 제한합니다. 나머지는 화면 진입 시 1회 조회합니다.
- 현재 최대 50개 수준을 넘지 않게 합니다.
- 반·차시가 많아지는 경우를 대비한 차시별 요약 문서 설계는 보고서에 제안만 합니다.
