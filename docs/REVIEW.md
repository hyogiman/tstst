## 1. 전체 구조와 UI 흐름 진단

### 1-1. 현재 정보 구조(IA)

```
[수강생 index.html]                 [강사 admin.html]
로그인/가입                          로그인 (가입 없음, role=admin 필요)
 └ 수강코드 입장                      ├ 대시보드
 └ 하단 탭 6개                        ├ 클래스 관리 ─┬ (반 클릭) 수강생 관리
    ├ 과제   (주차 선택)              │              └ 반 수정 모달(차시·날짜)
    ├ 복습   (주차 선택)              ├ 주차별 콘텐츠 (목록 + 편집: 과제/퀴즈/다음차시)
    ├ 다음차시 (주차 선택)            ├ 과제·복습 관리 (주차 선택 → 학생 목록 → 상세)
    ├ 질문                            ├ 질문함
    ├ 우리 반                         └ 출석체크
    └ 내 정보 (프로필+출석)
```

### 1-2. 구조적 문제점

**(1) '주차 / 차시 / 회차' 용어가 혼재합니다.**
- 반 수정 모달은 "차시별 수업 날짜"(`admin.html:622` 부근), 주차 메뉴는 "새 주차", 학생 화면은 "다음차시", 출석은 "수업 차시 · 날짜".
- 게다가 **차시를 만드는 경로가 두 곳**입니다: ① 반 수정 모달의 "+ 차시 추가" ② 주차 콘텐츠의 "+ 새 주차". 두 경로가 `class.schedule`과 `weeks` 컬렉션을 각각 갱신하므로, 정렬 번호·날짜가 어긋날 여지가 있습니다(요약표 #5).
- 👉 **제안:** 용어를 **"회차(Sesión)"** 하나로 통일하고(주 2회 수업이면 '주차'는 틀린 말이 됨), 회차 생성은 한 곳(클래스 관리)에서만. 주차 콘텐츠 화면은 "회차별 학습자료"로 이름을 바꾸고 생성 버튼을 제거하거나, 같은 함수를 호출하도록 통일.

**(2) '다음 차시 안내'의 소속이 헷갈립니다.**
- 3주차 문서 안에 '4주차 예고'가 들어가는 구조라, 학생이 주차 선택기에서 "3주차"를 골랐는데 내용은 4주차 이야기입니다.
- 이 시스템의 본질은 사용자 말씀대로 **"학습 전후 커뮤니케이션"**입니다. 그렇다면 회차 하나를 다음처럼 **시간 축**으로 정의하는 편이 자연스럽습니다.

```
N회차 ─┬─ 수업 전 (Antes de clase)  : 예습 자료, 영상, 준비 질문
       ├─ 수업 당일                    : 출석
       └─ 수업 후 (Después de clase) : 과제, 복습 퀴즈, 피드백, 한 줄 소감
```
- 👉 학생 탭도 "과제/복습/다음차시" 대신 **"예습 · 복습"** 두 묶음으로 보여 주면 인지 부담이 줄어듭니다.

**(3) 학생 하단 탭 6개는 모바일에서 과밀합니다.**
- 390px 폭 기준 탭당 약 60px, 라벨 10~11px(`index.html:203`, `214`). 370px 이하에선 9px까지 줄어듭니다(`index.html:215`). 한국어 9px는 읽기 어렵습니다.
- 아이콘도 이모지(✍🏻, 💬)와 기호(✦, ▤, ♙, ◉)가 섞여 있어 기기별로 모양·크기가 달라집니다(`index.html:434`). 강사 페이지는 SVG 아이콘을 쓰는데 학생 페이지만 이모지입니다.
- 👉 **제안 (5탭):** `홈` · `학습`(예습/과제/복습 하위 탭) · `질문` · `출석`(또는 기록) · `내 정보`. '우리 반'은 '내 정보' 안으로 이동하거나 제거(5장 참고).

**(4) 강사 사이드바와 코드가 어긋나 있습니다.**
- `PAGES` 상수(`admin.html:555`)는 선언만 되고 쓰이지 않습니다(실제 메뉴는 `frame()` 안의 `sidebarEntries`). 메뉴 이름도 서로 다릅니다("제출·피드백" vs "과제 · 복습 관리", "반 관리" vs "클래스 관리"). 다음 수정 때 혼란의 원인이 되니 하나로 정리하세요.
- '수강생 관리'는 사이드바에 없고 반 이름을 눌러야만 들어갈 수 있습니다. 강사가 가장 자주 찾는 화면 중 하나이므로 최상위 메뉴로 올리는 것을 권합니다.

**(5) 학생 입장에서 "새로 생긴 것"을 알 방법이 없습니다.**
- 새 피드백, 새 답변, 새 과제 공개 모두 해당 탭에 직접 들어가야 확인됩니다.
- 실시간 구독(onSnapshot)은 잘 구현되어 있지만 **"그 화면을 열고 있을 때만"** 실시간입니다.
- 👉 탭 배지(●, 숫자)와 홈 화면 "새 소식" 카드가 필요합니다. 데이터 측면에선 `lastSeenAt` 같은 열람 시각 기록이 필요합니다(3장 데이터 모델 참고).

### 2-2. 과제 (수강생 제출 ↔ 강사 피드백)

**잘 된 점**
- 텍스트+음성 녹음/파일 업로드, 녹음 미리듣기, 업로드 진행률, 재제출 허용, 피드백 실시간 반영까지 흐름이 완성되어 있습니다.
- 피드백을 여러 개(배열)로 달 수 있고 텍스트+음성 모두 가능 — 스페인어 발음 교정에 매우 적합한 설계입니다.
- 동시 수정 충돌을 트랜잭션으로 검사하는 부분(`updateFeedbackItem`)은 꼼꼼합니다.

**개선 필요**

1. **재제출 시 이전 답안이 사라집니다.** `setDoc(..., {merge:true})`로 덮어쓰기라, 학생이 피드백을 받고 고쳐 낸 "Before → After"를 볼 수 없습니다. 언어 학습에서 이 변화가 가장 중요한 학습 증거입니다.
   👉 퀴즈처럼 `submissions/{uid}/versions` 하위 컬렉션에 버전을 쌓고, 강사 상세 화면에 "1차 제출 / 수정 제출" 비교 보기를 제공하세요.
2. **피드백이 어느 버전에 달린 것인지 모릅니다.** 재제출 후에도 예전 피드백이 그대로 붙어 있어 맥락이 흐려집니다. 피드백에 `versionId`를 함께 저장하세요.
3. **마감 개념이 '권장일'뿐이고 제출 시각 대비 판정이 없습니다.** `dueAt`이 시간대 없는 문자열(`datetime-local`)로 저장되고 화면에도 `2026-10-28 18:00`처럼 원문 그대로 노출됩니다(`index.html:528`).
   👉 표시용 포맷 함수 적용 + 제출 시 `onTime: true/false` 계산 저장 → 대시보드 "기한 내 제출률" 지표로 활용.
4. **음성 외 파일 제출 불가.** 손글씨 작문 사진, 문장 카드 이미지 등을 내고 싶은 경우가 생깁니다. 이미지 1장 첨부 정도는 추가 가치가 큽니다.
5. **녹음 길이 정보가 없습니다.** 말하기 과제의 "발화량(초)"은 학습분석에서 의미 있는 지표입니다. 녹음 종료 시 `duration`을 함께 저장하세요.
6. 강사 피드백 작성 시 **자주 쓰는 피드백 문구(템플릿)** 기능이 있으면 학생이 많을 때 시간을 크게 줄입니다. (예: "acento 위치 확인!", "ser/estar 구분 다시 보기")
7. 피드백을 학생이 **읽었는지** 강사가 알 수 없습니다 → `feedbackSeenAt` 기록.

### 2-3. 복습 퀴즈

**잘 된 점**
- 객관식/복수정답/OX, 선택지 셔플, 이전 구조(`correctIndex`) 호환, 첫 응시와 최근 응시 분리 저장, 응시 이력 하위 컬렉션 — 학습분석 관점에서 **"첫 응시 정답률"을 따로 보관하는 설계는 매우 좋습니다.** 재응시 점수는 '외운 정도', 첫 응시는 '실제 이해도'에 가깝기 때문입니다.

**개선 필요**

1. **정답이 학생 브라우저에 그대로 내려갑니다.** 주차 문서의 `quiz.questions[].correctIndices`를 학생이 읽으므로 개발자도구로 정답 확인이 가능하고, 점수도 학생 브라우저에서 계산해 저장합니다(`index.html:598-608`). 복습용 저부담 퀴즈라면 수용 가능하지만, 성적 반영 용도로 쓰면 안 됩니다. 이 한계를 강사 화면에 명시해 두거나, 추후 Cloud Functions로 채점 이전을 고려하세요.
2. **답안을 '문항 순서 번호'로 저장합니다.** 강사가 퀴즈를 수정(문항 삭제·순서 변경)하면 과거 답안 해석이 틀어집니다(코드에도 경고 문구 존재, `admin.html` 응시기록 영역). 문항에 이미 `id`가 있으므로 `answers: {문항id: 선택값}` 형태로 저장하면 해결됩니다.
3. **신규 첫 응시 객체에 `answers`가 없습니다**(`index.html:604`, `legacy:false` 분기). 첫 응시 답안은 attempts 1회차에만 남습니다. 문항 분석을 하려면 attempts를 매번 읽어야 하니 `firstAttempt.answers`도 함께 저장하세요.
4. **문항 유형 확장 제안(스페인어 특화)** — 현재 3종은 '인식(recognition)' 위주라 '산출(production)' 연습이 부족합니다.
   - **단답 입력형**: "‘감사합니다’를 스페인어로" → `gracias`. 악센트(á, é, ñ) 유무를 '부분 정답'으로 처리하는 옵션이 핵심입니다.
   - **듣기형**: 문항에 음성 첨부 → 듣고 고르기
   - **동사 변화 표 채우기**(yo/tú/él…)
   - **문장 배열형**(단어 카드 순서 맞추기)
5. **오답만 다시 풀기** 버튼 — 결과 화면에서 틀린 문항만 재응시하게 하면 복습 효율이 올라갑니다.
6. 퀴즈 결과 화면에서 이전 피드백(`z.last`)을 다시 그리는데, 위쪽 실시간 피드백 영역과 중복 표시됩니다(`index.html:569`, `612`).

### 2-4. 다음 차시 안내(예습 자료)

- 서식 편집기(`contenteditable` + `execCommand`), 이미지 모드, 다중 영상, 첨부파일 — 기능은 충분합니다. sanitize 함수로 XSS를 막은 점도 좋습니다.
- ⚠️ `document.execCommand`는 표준에서 폐기(deprecated) 예정 API입니다. 당장은 동작하지만, 장기적으로는 가벼운 에디터(예: Quill, Tiptap)로 교체를 고려하세요.
- ⚠️ **영상 2GB를 Firebase Storage에 직접 올리는 구조**는 비용(저장+다운로드 트래픽)이 빠르게 늘어납니다. 학생 20명 × 영상 500MB × 2회 시청이면 회차당 약 20GB 전송입니다. **YouTube '일부 공개' 또는 Vimeo 링크 임베드 옵션**을 추가하고 직접 업로드는 짧은 클립용으로 제한하는 것을 권합니다. (다운로드 숨김 처리는 코드 주석대로 완전한 보호가 아닙니다.)
- 학생이 예습 자료를 **열어봤는지 / 영상을 끝까지 봤는지** 기록이 없습니다 → 대시보드 "예습 참여율"의 전제 데이터(3장).
- 저장 버튼을 누르기 전 업로드된 파일은 Storage에 남습니다. 저장하지 않고 화면을 떠나면 고아 파일이 생깁니다(`admin.html:1006` 부근 안내문으로만 처리). 화면 이탈 시 경고(`beforeunload`) 추가 권장.

### 2-5. 질문함

- 학생 질문 → 강사 답변 → 스레드 대화가 잘 동작하며, 학생 이름을 최신 프로필로 갱신해 보여주는 처리도 세심합니다.
- 🐞 **(요약 #2)** 학생이 답장을 달 때 `replies`에만 추가하고 질문의 `status`를 바꾸지 않습니다(`index.html:669`). 강사 목록에는 계속 "답변 완료"로 보여 **후속 질문을 놓치게 됩니다.** 학생 답장 시 `status:'open', lastActivityAt` 갱신이 필요합니다(Rules에서 학생의 해당 필드 수정 허용 필요).
- 질문 목록 정렬이 '작성일' 기준이라 오래된 질문에 새 답장이 와도 아래에 묻힙니다 → `lastActivityAt` 기준 정렬.
- 질문에 **회차 연결·주제 태그**(문법/발음/어휘/과제 관련/기타)가 있으면 "어느 회차에서 질문이 몰렸나"를 분석할 수 있습니다.
- 사진 첨부(교재 페이지 촬영) 수요가 높을 것입니다.
- 자주 나오는 질문을 반 전체에 공개하는 **FAQ 전환** 기능 고려(질문자 익명 처리).

### 2-6. 출석

- 🐞 **(요약 #1)** 빠른 출석체크 화면은 `present`인 학생만 체크된 상태로 불러오고(`admin.html:1198`), 저장 시 체크 안 된 모든 학생을 `absent`로 씁니다(`admin.html:1206`). 따라서 **이전에 '지각'·'인정결석'으로 바꿔 둔 학생이 결석으로 덮어써집니다.** 화면에는 "지각"이라고 표시까지 되는데 체크박스는 꺼져 있어서 더 위험합니다.

## 3. 대시보드 — 학습분석 관점의 제안

### 3-1. 현재 대시보드 평가

현재 구성: 브랜드 배너 → KPI 4개(수강생 수, 출석률, 과제 제출률, 복습 첫 정답률) → 회차별 출석률 막대 → 운영 현황 4줄 → 회차별 과제 제출률 막대 → 집계 기준 설명.

**좋은 점**
- 읽지 못한 데이터를 0으로 계산하지 않고 오류로 표시하는 원칙(`admin.html:731`), 집계 기준을 화면 하단에 명시한 점은 **데이터 리터러시 측면에서 모범적**입니다.
- '첫 응시 정답률'을 KPI로 고른 것도 좋은 판단입니다.

**한계**
1. **"그래서 무엇을 해야 하나?"가 보이지 않습니다.** 모든 지표가 반 평균이라, 출석률 85%를 보고 '누가' 결석했는지는 다른 메뉴로 가야 압니다.
2. **피드백 대기 건수가 없습니다.** 강사에게 가장 중요한 업무 지표인데, 질문 대기만 있고 과제 피드백 대기는 '과제·복습 관리' 화면 안에만 있습니다.
3. **퀴즈 추이 차트가 없습니다.** KPI 숫자 하나뿐입니다.
4. **아직 마감 전인 회차도 제출률에 포함**되어(`admin.html:746`) 이번 주 과제가 공개된 직후엔 제출률이 급락해 보입니다.
5. **상단 브랜드 배너가 화면의 첫 1/4을 차지**합니다(`admin.html:715`). 매일 보는 업무 화면에서 장식 이미지는 데이터를 아래로 밀어냅니다.

### 3-2. 재구성 제안: "세 가지 질문"에 답하는 대시보드

> 대시보드는 '숫자 진열장'이 아니라 '의사결정 도구'여야 합니다. 강사가 대시보드를 열 때 실제로 묻는 질문은 세 가지입니다.

```
┌──────────────────────────────────────────────────────────────┐
│ ① 오늘 할 일 (Action Queue)                                   │
│   피드백 대기 7건 · 미답변 질문 2건 · 오늘 19:00 3회차 출석체크 │
│   · 다음 회차 예습자료 미공개                                  │
├──────────────────────────────────────────────────────────────┤
│ ② 반 전체가 잘 따라오고 있나? (Class Pulse)                    │
│   KPI 5개 + 회차별 학습 퍼널 + 퀴즈 추이 + 문항 분석            │
├──────────────────────────────────────────────────────────────┤
│ ③ 누구를 챙겨야 하나? (Students to watch)                      │
│   관심 필요 학생 리스트 + 학생×회차 히트맵                      │
└──────────────────────────────────────────────────────────────┘
```

#### ① 오늘 할 일 (클릭하면 해당 화면으로 바로 이동)

| 카드 | 계산 | 데이터 상태 |
|------|------|-------------|
| 피드백 대기 | 제출됨 & 피드백 0건 & (재제출이 마지막 피드백보다 최신) | ✅ 현재 데이터로 가능 |
| 미답변 질문 | `status !== 'answered'` (+ 학생 후속답장 버그 수정 필요) | ✅ (버그 수정 후) |
| 오늘 수업 | `schedule.date === 오늘` → 출석체크 바로가기 | ✅ |
| 콘텐츠 공개 누락 | 다음 수업일이 3일 이내인데 해당 회차 `published=false` 또는 예습자료 OFF | ✅ |
| 질문 평균 응답 시간 | `answeredAt − createdAt` 중앙값 | ✅ (`answeredAt` 이미 저장 중) |

#### ② 반 전체 현황 — 추가 지표 제안

**(a) 회차별 학습 퍼널 (가장 추천)**
한 회차의 "수업 전 → 수업 → 수업 후" 참여를 한 줄 막대로 봅니다.

```
3회차  예습 열람 18/20 ▸ 출석 17/20 ▸ 과제 제출 14/20 ▸ 퀴즈 응시 15/20 ▸ 피드백 확인 9/14
```
- 어느 단계에서 이탈이 큰지가 보입니다. 예: "출석은 높은데 과제가 낮다 → 과제 난이도·분량 점검", "피드백 확인율이 낮다 → 피드백 전달 방식 점검".
- 필요 데이터: 예습 열람(`views` 기록), 피드백 확인(`feedbackSeenAt`) — **신규 기록 필요**.

**(b) 퀴즈: 첫 응시 vs 최종 응시 추이 (꺾은선 2개)**
- 두 선의 간격 = "복습으로 끌어올린 만큼". 간격이 0이면 재응시를 안 한다는 뜻 → 재응시 유도 필요.
- ✅ 현재 데이터(`firstAttempt`, `score`)로 가능.

**(c) 문항 분석 (Item Analysis) — 강사에게 가장 실용적인 지표**
- **문항 난이도(정답률 p)**: 첫 응시 기준 정답자 비율. 고전검사이론(Classical Test Theory)의 기본 지표로, 일반적으로 p가 매우 낮은(예: 0.3 미만) 문항은 "어려운 개념이거나 문항이 모호함" 신호로 봅니다.
- **오답 선택지 분포(distractor analysis)**: "학생 60%가 같은 오답을 골랐다" = 공통 오개념. 스페인어라면 *ser/estar*, *por/para*, 성·수 일치 같은 지점이 이렇게 드러납니다. **다음 수업 도입부 5분을 이 문항 해설에 쓰는 것**이 데이터 기반 수업 설계의 가장 쉬운 시작입니다.
- (선택) **변별도**: 상위 집단과 하위 집단의 정답률 차이. 학생 수가 적은 소규모 반(10명 내외)에서는 통계적으로 불안정하니 참고용으로만 표기하세요.
- ✅ attempts 1회차 답안으로 가능 (단, 2-3의 "문항 id 기반 저장"으로 바꿔야 문항 수정 후에도 정확).

**(d) 기한 내 제출률 & 제출 시점 분포**
- "수업 후 24시간 이내 / 마감 전 / 마감 후 / 미제출" 4구간 누적 막대.
- 망각곡선(에빙하우스, 1885)이 시사하듯 학습 직후 복습이 기억 유지에 유리하므로, "수업 후 며칠 만에 복습했나"는 학습 습관 지표로 의미가 있습니다.
- 필요 데이터: 마감 시각의 정규화(타임존 포함), `submittedAt`(이미 있음).

**(e) 말하기 발화량**
- 회차별 음성 제출 수, 총 녹음 시간(초). 회화 중심 강의라면 "말한 양"은 정직한 노력 지표입니다.
- 필요 데이터: 녹음 `duration` 저장 — **신규**.

**(f) 기술(Skill) 영역별 성취**
- 퀴즈 문항·과제에 태그를 달면(어휘 / 문법 / 듣기 / 말하기 / 쓰기, 혹은 문법 주제) 영역별 정답률 레이더 차트가 가능합니다.
- 참고 프레임워크: **CEFR(유럽언어공통참조기준)** A1~C2 — 스페인어권 공인 시험 DELE도 이 체계를 따릅니다. 반 레벨을 A1/A2 등으로 지정해 두면 "A1 목표 어휘 중 몇 %를 다뤘나" 같은 커리큘럼 관점 분석으로 확장할 수 있습니다.

**(g) 학습자 자기평가 (Exit Ticket) — 정량 데이터가 놓치는 것을 보완**
- 매 회차 종료 후 30초 설문: ① 오늘 이해도(1~5) ② 자신감(1~5) ③ "가장 헷갈렸던 한 가지".
- ③은 Angelo & Cross의 『Classroom Assessment Techniques』(1993)에 소개된 대표 기법 **"Muddiest Point(가장 흐릿했던 점)"** 입니다. 짧고 부담이 적어 매 회차 반복하기 좋고, 강사가 다음 수업을 조정하는 근거가 됩니다.
- **자기평가 vs 퀴즈 점수 비교(보정, calibration)**: "자신감은 높은데 점수가 낮은" 학생은 착각된 유창성(illusion of fluency)을, "자신감은 낮은데 점수가 높은" 학생은 격려가 필요한 경우로 볼 수 있습니다.
- 필요 데이터: `weeks/{id}/checkins/{uid}` — **신규 컬렉션**.

#### ③ 누구를 챙겨야 하나 — 관심 필요 학생

**학생 × 회차 히트맵** (소규모 반에서 가장 직관적)

```
          1회  2회  3회  4회  5회
김OO      ●✓  ●✓  ●✓  ●✓  ●·
이OO      ●✓  ○✗  ○✗  ●·  ○·     ← 2회 연속 결석 + 미제출
박OO      ●✓  ●✓  ◐✓  ●✓  ●✓
           ● 출석 ◐ 지각 ○ 결석  ✓ 과제 제출 ✗ 미제출 · 해당없음
```
- 셀 색은 퀴즈 첫 응시 점수, 아이콘은 출석/과제. 클릭 → 학생 상세.

**관심 필요 학생 규칙(초안, 강사가 기준값 조정 가능하게)**
- 최근 3회차 중 결석 2회 이상
- 공개된 과제 2개 연속 미제출
- 최근 퀴즈 첫 응시가 반 평균보다 20%p 이상 낮음
- 2주 이상 아무 활동(제출·응시·질문·열람) 없음
- 화면에는 반드시 **이유를 함께** 표기: "이OO — 2회 연속 결석, 3회차 과제 미제출"

> **참고 사례와 주의점:** 미국 퍼듀대학의 *Course Signals*(2007년경 도입)는 학습관리시스템 데이터로 학생에게 신호등(초록·노랑·빨강)을 보여 주는 조기경보 시스템의 대표 사례입니다. 다만 이 시스템이 '졸업률을 높였다'는 초기 주장에는 이후 통계적 방법론 문제가 지적되었습니다(2013년경 Michael Caulfield 등). 교훈은 두 가지입니다. ① 경보는 '판정'이 아니라 '대화의 계기'로 써야 하고 ② 지표가 실제 학습을 대변하는지 계속 의심해야 한다는 것. 그래서 **학생에게는 '빨간불'을 보여 주지 말고, 강사만 보는 '안부 연락 리스트'로** 쓰기를 권합니다.

### 3-3. 대시보드 지표 우선순위 (구현 난이도 × 가치)

| 우선 | 지표 | 신규 데이터 필요 | 난이도 |
|:---:|------|:---:|:---:|
| ★★★ | 오늘 할 일(피드백 대기·미답변·오늘 수업) | ✕ | 하 |
| ★★★ | 학생×회차 히트맵 | ✕ | 중 |
| ★★★ | 관심 필요 학생 리스트(+이유) | ✕ | 중 |
| ★★★ | 문항별 정답률·오답 분포 | △(문항 id 저장 권장) | 중 |
| ★★☆ | 첫 응시 vs 최종 응시 추이 | ✕ | 하 |
| ★★☆ | 기한 내 제출률 / 제출 시점 분포 | △(마감시각 정규화) | 하 |
| ★★☆ | 질문 응답 시간 | ✕ | 하 |
| ★★☆ | Exit Ticket(이해도·Muddiest Point) | ○ | 중 |
| ★☆☆ | 회차별 학습 퍼널(예습 열람·피드백 확인) | ○ | 중 |
| ★☆☆ | 말하기 발화량 | ○(duration) | 하 |
| ★☆☆ | 기술 영역별 레이더(태그) | ○(태그 입력 UI) | 상 |
| ★☆☆ | 기수(반) 간 같은 회차 비교 | ✕ | 중 |

마지막 항목 **"기수 간 비교"**는 회차별로 반을 반복 운영하는 구조에서 특히 가치가 있습니다. "1기와 2기의 4회차 퀴즈 정답률이 모두 낮다 → 반 탓이 아니라 4회차 교안 문제"라는 결론을 낼 수 있기 때문입니다. 이는 커크패트릭(Kirkpatrick) 4단계 평가 모형으로 보면 Level 2(학습) 데이터를 **교육 설계 개선**에 되먹임하는 구조입니다 — 기업교육 담당자 입장에서 익숙한 관점일 것입니다.

### 3-4. 측정에 대한 인문학적 성찰 (대시보드 설계 원칙으로)

- **굿하트의 법칙(Goodhart's Law)** — 인류학자 메릴린 스트래선이 정리한 표현으로 널리 알려진 "측정치가 목표가 되면, 그것은 더 이상 좋은 측정치가 아니다." 제출률을 학생에게 경쟁적으로 보여 주면, 학생은 '배우기 위해'가 아니라 '제출률을 위해' 빈 답안을 냅니다. → **학생 화면에는 비교·순위 지표를 두지 말고, '나의 어제 대비 오늘'만** 보여 주세요.
- **해티 & 팀펄리(Hattie & Timperley, 2007) "The Power of Feedback"** — 좋은 피드백은 세 질문에 답합니다: *Where am I going?(목표)* *How am I going?(현재)* *Where to next?(다음 단계)*. 강사 피드백 입력창을 "잘한 점 / 고칠 점 / 다음에 해 볼 것" 3칸 템플릿으로 바꾸면, 이 원칙이 자연스럽게 시스템에 녹아듭니다.
- 스페인어 속담 **"Poco a poco se va lejos(조금씩, 조금씩 가면 멀리 간다)"** — 학생 홈 화면의 진척 표시(연속 학습 주차, 누적 녹음 시간)를 이 철학으로 설계하면 브랜드 메시지("오늘의 스페인어가 내일의 일상이 되도록")와도 일치합니다.

### 3-5. 학생용 '나의 학습' 대시보드 (마이페이지 확장)

현재 학생 마이페이지는 프로필 + 출석 목록뿐입니다. 학생 본인용으로 다음을 제안합니다.
- 출석률, 과제 제출 수, 퀴즈 첫 응시 → 최종 점수 추이(본인만)
- 누적 녹음 시간 ("지금까지 스페인어로 12분 47초를 말했어요")
- 받은 피드백 모아보기(회차별) — 학생이 자신의 성장 기록을 돌아보는 '포트폴리오'
- 틀린 문항 모아보기 → '오답 노트 퀴즈'로 재응시

## 4. 디자인 · UI 검토

### 4-1. 근본 원인: 디자인 레이어가 10겹 덧칠되어 있음

두 파일 모두 CSS가 다음처럼 누적되어 있습니다.

```
기본(녹색 테마) → v2 "warm editorial"(네이비·코랄) → v3 퀴즈 → v4 Brand System(와인레드)
→ v5 polished admin → v6 대시보드 레퍼런스 → v7 클래스 → v8 대시보드 → v9 피드백 → v10 주차/로그인
```

- `:root` 색 변수 3회 재정의, `!important` admin 43개·index 34개, 고유 HEX 색상 455개(admin).
- 같은 선택자(`.pill.green` 등)가 3번씩 다른 색으로 정의되어 **마지막 것이 이기는 구조** → 어떤 색이 최종인지 코드만 봐서는 알기 어렵고, 한 곳을 고쳐도 다른 레이어가 덮어씁니다.
- 초기 녹색 테마 잔재: 퀴즈 정답 체크 색 `#26785e`(`.quiz-choice-mark input`), OX 라벨 `#235f48`, 로그인 eyebrow `#c5ead6` 등.

👉 **제안:** 최종 브랜드(와인 레드 `#b4233b`) 기준으로 **디자인 토큰 1벌**만 남기고 재작성.

```css
:root{
  /* 브랜드 */
  --brand-700:#84152d; --brand-600:#b4233b; --brand-50:#fff0f2;
  /* 중립 */
  --ink:#2b2226; --muted:#7a6a70; --line:#efe3e5; --bg:#fdf8f6; --surface:#fff;
  /* 의미 색 (브랜드 색과 반드시 분리!) */
  --success:#1f7a4d; --success-bg:#e8f5ee;   /* 정답·출석·완료 */
  --warning:#9a5b12; --warning-bg:#fff3e0;   /* 지각·대기 */
  --danger:#b3261e;  --danger-bg:#fdecea;    /* 오답·결석 */
  --neutral:#6b6f76; --neutral-bg:#f1f2f4;   /* 미체크·해당없음 */
  /* 간격·모서리 */
  --r-sm:8px; --r-md:12px; --r-lg:18px;
}
```

### 4-2. 의미 색(Semantic color) 문제 — 요약 #3

- 현재 `.pill.green` = 배경 `#fce8ed` / 글자 `#9a1b32`(분홍·와인), `.pill.red` = 배경 `#fff0f2` / 글자 `#a72742`(분홍·와인). **사실상 같은 색**입니다.
- 이 배지가 쓰이는 곳: 퀴즈 결과 정답/오답, 출석/결석, 답변 완료/대기, 공개/비공개, 제출/대기.
- 브랜드 색을 빨강으로 정했다면, **"빨강 = 오류/위험"이라는 보편적 의미와 충돌**하므로 정답·완료에는 반드시 녹색 계열을 별도로 써야 합니다. 색약 사용자를 위해 색 + 아이콘(✓ ✗ ⏱) 병기도 권장합니다.

### 4-3. 조잡해 보이는 요소 / 덜어낼 것

| 요소 | 위치 | 제안 |
|------|------|------|
| 대시보드 상단 대형 브랜드 배너 | 강사 대시보드 | 제거 또는 높이 1/3로 축소. 브랜드는 사이드바 로고로 충분 |

| 안내 문구 과다 (`hint` 문단) | 주차 편집, 출석 등 | 필수 안내만 남기고 나머지는 `ⓘ` 툴팁으로 |
| 각 화면마다 다른 '목록+상세' 레이아웃 | 주차/피드백/질문 | 3개 화면이 각자 다른 CSS(`.week-workspace`, `.feedback-workspace`, `.questions-workspace`)로 구현됨 → 공통 `master-detail` 컴포넌트 1개로 통일 |

### 4-4. 접근성 · 모바일

- 학생 하단 탭 라벨 9~11px → 최소 12px 권장.
- 버튼 `min-height:33~37px` 소형 버튼이 많음 → 모바일 터치 타깃 최소 44px 권장(Apple HIG 기준).
- `aria-live`, `role="dialog"`, `aria-pressed` 등은 잘 챙겨져 있음 ✅. 다만 모달 열린 상태에서 Tab 키 포커스가 모달 밖으로 나가는 것을 막는 **포커스 트랩**이 없음.
- `prefers-reduced-motion` 대응 ✅.
- 다크모드 미지원 — 필수는 아님.

## 5. 필요 없어 보이는 내용 / 추가가 필요한 화면

### 5-1. 덜어내거나 재검토할 것

1. **학생 '우리 반' 탭** — 현재는 반 친구 이름 목록뿐입니다. 소규모 강의에서 동료 의식은 의미가 있지만 탭 하나를 차지할 가치는 낮습니다. 대안: ① 제거하고 '내 정보' 안 작은 카드로 ② 또는 '함께 배우기'로 발전 — 강사가 고른 우수 과제(동의 시) 공유, 반 공지, FAQ 등.
2. **대시보드 브랜드 배너**(4-3).
3. **'주차 콘텐츠' 화면의 '+ 새 주차'** — 회차 생성 경로를 클래스 관리로 일원화(1-2).
4. **미사용 코드**: `PAGES` 상수, 녹색 테마 CSS, DM Sans 폰트, 중복 파비콘, 구버전 데이터 복구 로직(마이그레이션 1회 후 제거 가능: '수강생' 이름 복구, `correctIndex` 호환, `feedback` 단일 필드 호환).

### 5-2. 추가가 필요한 화면

| 화면 | 사용자 | 핵심 내용 | 우선 |
|------|--------|-----------|:---:|
| **학생 홈 (오늘 할 일)** | 학생 | 다음 수업 일시 D-day, 이번 회차 체크리스트(예습 열람 / 과제 / 퀴즈), 새 피드백·답변 알림, 최근 진척 | ★★★ |
| **학생 상세(학습 프로파일)** | 강사 | 한 학생의 출석·과제(버전 비교)·퀴즈 추이·질문·강사 메모를 한 화면에. 상담·면담 시 그대로 활용 | ★★★ |
| **공지사항** | 강사→학생 | 휴강·보강·준비물 안내. 지금은 전달 수단이 없음 | ★★★ |
| **회차 종료 체크인(Exit Ticket)** | 학생→강사 | 이해도·자신감·Muddiest Point 30초 설문 | ★★☆ |
| **문항 분석 리포트** | 강사 | 회차별 퀴즈 문항 정답률, 오답 분포 | ★★☆ |
| **오답 노트** | 학생 | 틀린 문항 모아 다시 풀기 | ★★☆ |
| **피드백 문구 템플릿 관리** | 강사 | 자주 쓰는 피드백 저장/삽입 | ★★☆ |
| **기수 종료 리포트(수료 리포트)** | 강사→학생 | 출석률, 제출 수, 누적 말하기 시간, 강사 총평 — PDF/이미지로 발급하면 수강생 만족·재등록에 도움 | ★☆☆ |
| **콘텐츠 복사(이전 기수 → 새 기수)** | 강사 | 회차별 과제·퀴즈·예습자료를 새 반으로 복제. 회차별로 반을 반복 운영한다면 **매 기수 수작업 재입력을 없애는 핵심 기능** | ★★★ |

> 마지막 '콘텐츠 복사'는 사용자 설명("회차별로 수강생을 관리")을 볼 때 운영 부담을 가장 크게 줄일 기능이라 ★★★로 올렸습니다. 현재 코드에는 반 간 콘텐츠 복제 기능이 없습니다.

```
classes/{cid}
  level: 'A1'                                   # (신규, 선택) CEFR 레벨

      feedbackSeenAt: Timestamp                  # (신규) 학생이 피드백 확인한 시각
      onTime: boolean                            # (신규) 기한 내 제출 여부
    quizResults/{uid}

      attempts/{aid}.answers: {qid: value}       # (변경) 문항 id 기반

    checkins/{uid} {understanding, confidence, muddiest, createdAt}  # (신규) Exit Ticket
  questions/{qid}
    lastActivityAt, weekId, tag                  # (신규)
  announcements/{aid}                            # (신규) 공지
users/{uid}
  lastSeen: {feedback: Timestamp, replies: Timestamp}  # (신규) 읽음 배지용
```

## 7. 단계별 수정 로드맵 (함께 작업할 때 순서 제안)

**1단계 — 버그·신뢰성 (반나절~1일)**
- [ ] 빠른 출석체크 지각/인정결석 덮어쓰기 수정
- [ ] 학생 답장 시 질문 상태 `open`으로 + `lastActivityAt` 정렬
- [ ] 의미 색(성공/경고/위험/중립) 분리
- [ ] 확인 모달 라벨·제목 파라미터화
- [ ] 수강 중지 학생도 새 수강 코드 입력 가능하게
- [ ] `firestore.rules` / `storage.rules` 저장소에 추가 및 점검
- [ ] 주차 정렬 번호 변경 시 schedule 순서 동기화

**2단계 — 구조 정리 (2~3일)**
- [ ] `common.css` / `common.js` 분리, CSS 1벌 재작성(디자인 토큰)
- [ ] 용어 '회차'로 통일, 회차 생성 경로 일원화
- [ ] 학생 하단 탭 5개로 재편 + 학생 홈 화면
- [ ] 새 피드백·답변 배지

**3단계 — 학습분석 (3~5일)**
- [ ] 대시보드 '오늘 할 일' + 학생×회차 히트맵 + 관심 필요 학생
- [ ] 퀴즈 답안 문항 id 기반 저장 → 문항 분석 화면
- [ ] 과제 제출 버전 관리 + 강사 비교 보기
- [ ] 학생 상세(학습 프로파일) 화면

**4단계 — 확장**
- [ ] Exit Ticket, 공지사항, 오답 노트, 피드백 템플릿
- [ ] 기수 간 콘텐츠 복사, 기수 간 비교 리포트
- [ ] 단답형·듣기형 퀴즈, 영상 외부 링크 임베드

### 부록: 검토 중 확인하지 못한 것 (정직한 한계)

- Firebase 콘솔의 **실제 보안 규칙**, 인덱스, Storage 규칙 — 저장소에 없어 검증 불가.
- **실제 화면 렌더링** — 검토 환경에서 Firebase CDN(gstatic.com) 접속이 차단되어 로그인 이후 화면을 띄우지 못했습니다. 디자인 평가는 CSS 코드 분석 기준이며, 스크린샷을 주시면 시각적으로 한 번 더 검토하겠습니다.
- 사용 중인 Firebase JS SDK `13.1.0` 버전의 정확한 릴리스 상태 — 네트워크 제약으로 확인하지 못했습니다.
- 위 3-2의 참고 문헌·사례(Angelo & Cross 1993, Hattie & Timperley 2007, Purdue Course Signals와 그 비판, 굿하트의 법칙, 에빙하우스 망각곡선, CEFR, Kirkpatrick 모형)는 실재하는 자료이나, 교안 등에 인용하실 때는 원문 출처를 한 번 더 확인하시길 권합니다.
